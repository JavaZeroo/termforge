# WindTerm 2.7.0：活动区域缩宽与保存末列返回

本目录记录 [固定 resize-mode 协议](../../resize_mode_reference.md)的原版观察，用于 #27/#29。共归档三个独立原版进程的 **16 个阶段**，三例机械审计及严格导出均通过。这里记录外部行为，不据此推断原版私有 origin 位、帧结构、保存光标或存储实现。

## 固定范围与来源

固定 WindTerm 2.7.0 x64、Windows VM `10.0.26300`、Python `3.12.10`、REA `6.7.0`。每例使用一个全新原版进程、一个合成 loopback Telnet 会话、独立且不可重放的计划。窗口 `1360×749 → 1000×749 → 1360×749`；实际 NAWS 为 `91×20 → 61×20 → 91×20`，高度不变。每阶段独立完成 DSR、正文/矩形观察和 ack 后才执行下一动作。

运行源码基点为 `45c53f583267185f6a832ef356994e0746176767`。三例的 10 份运行源码及 3 份导出器源码身份一致，完整清单见 JSON；归档时逐份核对源码 zip、manifest、提交内容与公开 SHA。源码 manifest SHA 为 `df9f2a2c13df2e6a6d97e055c9c05e7319385e287e4b83a439b974cb8dcffaaa`。原版 EXE SHA 为 `7b10531dccc7cd614ae559f36f1ef518e0c96335637431b4646354823b2804d0`，4047 文件包 manifest SHA 为 `e459adf2f12adb6a1b7f55e66a9da1c22794185e66e848057d21e0c60d669203`。

## 活动主屏与备用屏：相同的可观察寻址范围变化

两例都先固定 origin OFF、wrap ON 并清屏，在屏幕第 `1/2/3/4/5/6/20` 行、第 6 列写 `T0/R2/R3/R4/R5/B6/B0`；然后设置 margin `2..5`、origin ON，以 `CUP(2,10)` 写主屏 `MP` 或备用屏 `AP`。第 20 行只写两个字符，不触发末列换行。备用屏例先进入 `1049h`，整个观察期间不返回主屏。

以下 DSR 为一基；文档行列为零基；显示行按本次 18 像素行高描述。两例协议回复相同：

| 阶段 | 动作 | DSR | 可见观察 |
|---|---|---|---|
| 0 | 原始 `2..5` 区域、origin ON 初始化 | `2;12` | MP/AP 在显示行 2、列 9，矩形 `(219,36)` |
| 1 | 仅缩窄，不写 CUP 或正文 | `3;12` | 全部原有标记、正文摘要及矩形与阶段 0 相同 |
| 2 | `CUP(1,1)` 后写 UP | `1;3` | UP 在显示行 0、列 0，矩形 `(147,0)` |
| 3 | `CUP(99,1)` 后写 DN | `20;3` | DN 在显示行 19、列 0，矩形 `(147,342)` |
| 4 | 仅恢复宽度 | `20;3` | 正文与 marker 均保持阶段 3 结果 |

各阶段七个哨兵的显示位置始终不变：`T0/R2/R3/R4/R5/B6/B0` 的零基显示行分别为 `0/1/2/3/4/5/19`，列均为 5；MP/AP 始终在显示行 2、列 9。UP/DN 不覆盖这些哨兵。

主屏文档始终为 20 行、`scroll=0`。备用屏公开文档始终为 21 行、`scroll=1`：首行是空字符串，后续 20 行对应本例合成正文，所以 AP 在文档 `(3,9)`，UP/DN 在文档 `(1,0)/(20,0)`；它们的显示矩形与主屏相同。这个文档索引差异不是 C++ 通用映射应增加 `+1` 的规则，也不能证明备用屏拥有一行历史。

独立重建全部十阶段的完整字面数组，包括空格与中间空行，规范 JSON SHA 均匹配公开摘要。主屏初始数组在零基行 `0/1/2/3/4/5/19` 包含 `5 个空格 + 哨兵`，行 2 精确为 `5 个空格 + R3 + 2 个空格 + MP`，其余行为空字符串；备用屏将 MP 换成 AP 并在整个数组前加一条空字符串。阶段 2 只将显示首行前两个空格替换为 UP，阶段 3 只将显示末行前两个空格替换为 DN；阶段 1/4 的数组分别与 0/3 相同。所有 marker 的文档行列、累计 position 和矩形也逐项复算匹配。

这两例排除了“活动帧缩宽后仍保持原 `2..5` CUP 可达上下界”的行为：缩宽后控制可达显示第一行和第 20 行，未改动 DSR 也从区域相对行 2 变成行 3。**这不区分 origin 内部位是否关闭，或者区域变成全屏后 origin 仍保持**；报告不选择其中一种内部解释。本组不发送区域 LF，因此没有验证 resize 后滚动/历史行为；恢复宽度后也没有第二组 CUP 控制。

## 隐藏主屏的旧末列：先观察返回，再写 X

独立 `saved-primary-edge` 例明确设置 origin OFF、wrap ON，主屏写数字与 ANCHOR 锚点，再于旧 `CUP(8,91)` 写 W。随后进入备用屏写 AP，缩窄时主屏隐藏。`1049l` 返回与后续 X 是两个独立采样阶段，二者之间不插入 CUP。

| 阶段 | 动作 | DSR | 精确正文/marker 观察 |
|---|---|---|---|
| 0 | 主屏旧末列写 W | `8;91` | W 文档 `(7,90)`，position `113`，矩形 `(867,126)` |
| 1 | `1049h`，备用屏写 AP | `2;12` | AP 文档 `(9,9)`，position `125`，矩形 `(219,18)`；W 在文档保持，矩形 y 为 `-18` |
| 2 | 备用屏活动时仅缩窄 | `2;12` | AP 文档位置/矩形保持；W 文档位置保持，矩形变为 `(379,-18)` |
| 3 | 仅 `1049l`，原样返回主屏 | `8;61` | W 与 AP 消失；主屏文档末行精确为 **61 个空格** |
| 4 | 仅写 X | `8;61` | X 文档 `(7,60)`，position `83`，矩形 `(627,126)`；末行精确为 `60 个空格 + X` |
| 5 | 仅恢复宽度 | `8;61` | X 的文档位置、矩形及完整正文摘要均与阶段 4 相同，W 未复活 |

六阶段完整合成正文数组与 marker/source/display 投影均已独立复算匹配。共同主屏前七行依次为：空字符串、`0123456789`、`ANCHOR`、四条空字符串。阶段 0 在其后接 `90 个空格 + W`；阶段 1 再接一条空字符串和 `9 个空格 + AP`；阶段 2 额外增加一条末端空字符串。阶段 3 回到共同前七行加 61 个空格；阶段 4/5 改为共同前七行加 `60 个空格 + X`。文档行数为 `8→10→11→8→8→8`，`scroll=0→8→9→0→0→0`，capacity 始终为 20。

阶段 3 的正文 SHA 为 `d406c228d3792cc9550b15fdc7e4ea405e0be7c4a53d859b3159a5f2ef6da919`，阶段 4/5 为 `09574749f53998f85aa66dfbcb8083375c03543ddbdcd89a0ce16e573f1008bc`。这明确区分“返回时就已限制到新第 61 列、旧 W 已消失”和“直到 X 才触发处理”的外部结果。它没有定位原版在 resize、激活或其他内部步骤的处理时点；备用屏阶段公开文档仍出现 W，也不证明该文档副本就是隐藏帧内部存储。

下一 X 在同一显示行的新末列写入，没有转入下一行；不据此给内部 pending-wrap 位下定义，也不推广为任意保存/恢复光标序列。普通 `ESC 7/8`、`CSI s/u` 和 `1048` 未在本例执行。

## 未覆盖范围

这里不验证高度改变、宽字/结合字、样式、任意尺寸、单列、区域 LF、历史淘汰、在途输出及可靠性重复。它不构成正式 Qt 与固定 ConPTY 的联合验收，也不证明性能等价、完整 WindTerm 复刻或 R2 完成。现有 C++ 是否满足这些字面观察必须另行建立 RED/GREEN，不能由本报告代替实现验收。
