# WindTerm 2.7.0：固定正文在缩窄与恢复窗口后的观测

[#29](https://github.com/JavaZeroo/termforge/issues/29) 的一次受控原版样本：在合成 loopback Telnet 会话写入固定正文后，仅改变公开 QWidget 窗口宽度，再发送 DSR；后两阶段没有 CUP、补画正文或替换 marker。输入、三组 DSR、marker 标量、NAWS 与身份见 [strict-export.json](strict-export.json)。本记录区分协议光标、逻辑文档位置和可见矩形，不自动判定 TermForge 的 resize 策略已经匹配。

## 身份与固定条件

- 隔离 Windows 11 x64 VM，Python 观察到 `10.0.26300`；Python `3.12.10`、固定 REA `6.7.0`。没有补推 UBR、实际 DPI 或 glyph/font 身份。
- 官方 EXE SHA256：`7b10531dccc7cd614ae559f36f1ef518e0c96335637431b4646354823b2804d0`；4,047 文件清单 SHA256：`e459adf2f12adb6a1b7f55e66a9da1c22794185e66e848057d21e0c60d669203`。导出逐项复核源分发与执行副本的全部文件，以及 Qt 模块、执行模板和实际注入脚本。
- 执行源码基点 `f72c5c4f68dd7eb579ad1e523762333b135aa074`；独立 9 源归档清单 SHA256 `6bb2ed5067d5db933e7a22f91a41f429d31d66767fe1b525d7d1bc7ba1f24ee8`。基点不是新增探针已经提交的声明；实际身份由 JSON 内逐文件哈希确定。
- 成功样本的单次计划 SHA256：`1cdfbe755aba65f404d0cb3eb4302f53f86211c7c7597dc9e4b08eb700eac867`。窗口请求固定为 **1360×749 → 1000×749 → 1360×749**，测得 NAWS/capacity 为 **91×20 → 61×20 → 91×20**。QRect 按 inclusive left/top/right/bottom 解释，三阶段都要求实际窗口大小精确相等；完整 NAWS 事件和每次 resize 的握手边界保留。

## 三个坐标层的直接观察

正文包括 `0123456789`、`ANCHOR`，以及最初第 91 列的无自动换行 `uv` 与自动换行 `wx`。原版文档保留 `v` 于逻辑行 7、列 90；`w`、`x` 同在逻辑行 9 的列 90、91，后者构成长度 92 的逻辑行。这里的逻辑行、列为 API 的零基坐标。

| marker | 初始矩形 `(x,y)` | 缩窄后 | 恢复宽度后 |
|---|---|---|---|
| `ANCHOR` | `(147,36)` | `(147,36)` | `(147,36)` |
| `v` | `(867,126)` | `(379,144)` | `(867,126)` |
| `w` | `(867,162)` | `(379,198)` | `(867,162)` |
| `x` | `(147,180)` | `(387,198)` | `(147,180)` |

三阶段的文档 marker 位置保持不变，可见矩形发生上述重排并在恢复宽度后回到原位。DSR 三次都为 **`(11,2)`**（一基协议坐标），没有随 marker 可见矩形一起移动。因此本样本不能把 DSR、文档行列和显示坐标合并为同一层，也不能用单条 DSR 推断原版裁剪或光标恢复算法。

## 前置失败与导出检查

本次成功之前有两次独立新计划，各只尝试一次原版启动，均在初始尺寸检查阶段失败，**记录正文阶段数均为 0**：

1. 第一版误把 Qt5 QRect 的 right/bottom 当作 width/height，未取得可用的正文观测。
2. 修正 QRect 后仍要求 `1360×860`；实测 inclusive QRect 为 `[102,102,1461,850]`，实际大小为 `1360×749`。检查如实失败，未将受系统限制的高度当作请求成功。

旧计划、源码包和失败原件独立保留。成功版本依据第二次实测固定高度为 749，重新创建一次性计划；精确检查没有放宽。这三个原版 attempt 不是对同一份失败计划的重放，也不是三次 resize 成功。

首次离线导出又被“逻辑行长度不得超过初始列数”的过窄条件拒绝。该失败没有触发原版重跑。修正后的发布白名单只准许固定合成行：空串、`0123456789`、`ANCHOR`、90 个空格加 `v` 或 `w`、单独 `x`、90 个空格加 `wx`。长度 92 的唯一例外来自此处固定的 `wx`；溢出填充、重复后缀、私有文本及其他长行仍拒绝。正文全文不进入公开 JSON，导出前仅用于校验 marker 绑定与文本白名单。

## 局限

[探针](../../resize_state_reference.py)与[离线导出器](../../export_resize_state_reference.py)分别保存执行和发布身份。公开内容仅为固定合成输入、DSR、marker/窗口/NAWS 标量、哈希与 Evidence ID；私有路径、PID、profile、原始资源、全文记录不发布。离线检查覆盖错误身份、源/模块变化、部分结果、几何错误、额外终端输入、NAWS 越界及文本泄漏；这不代替原版行为判断。

原版窗口由自有启动器主动结束，Job 清空不是自然 GUI 退出证明。内部 41/42/43 秒期限、45 秒 REA 捕获和 60 秒 CLI 等待都不是整个生命周期的硬上限。此处只有一个正文、一个宽度收缩/恢复和 20 行高度，不包含完整 active grid、样式、其他高度/宽度、复杂 Unicode、滚动历史、选择/复制、真实本地 Shell 运输或性能验收，也不表示 #29 或 R2 已完成。
