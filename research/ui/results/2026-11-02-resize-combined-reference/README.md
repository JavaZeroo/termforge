# WindTerm 2.7.0：缩宽后缩高，再分别恢复高度与宽度

一次新进程完成 `91×20 → 61×20 → 61×14 → 61×20 → 91×20`。五阶段的完整 19 行合成文档完全相同，包括缩宽后仍位于源 offset 89/90/91 的 `uvw`；随后缩高没有裁掉这段右尾。DSR 为 **`19;7 → 19;7 → 14;7 → 14;7 → 14;7`**。恢复高度后 marker 矩形不变；最后恢复宽度只恢复宽度布局，保留缩高造成的纵向偏移。

这是固定顺序、主屏、ASCII、后续仅 DSR 的直接 Telnet 观察。`status=observation`、`semantic_acceptance=false`，不声明原版内部数据结构或 TermForge 组合尺寸实现已通过。

## 与已有观察的比较及实现约束

1. 本次阶段 0→1 是同一份 75 B 正文的单独缩宽对照：逻辑正文和 DSR 保持，`uvw` 按 61 列重新显示。这与[早先纯宽度样本](../2026-11-02-resize-state-reference/README.md)的“源位置保留、显示重排”现象一致；早先输入是另一份 78 B 正文与不同光标，不能拼作同一个样本或直接比较全部坐标。
2. 阶段 1→2 只改变高度，正文右尾仍完整，所有 marker 比阶段 1 上移 90 px。高度恢复后仍保持这个位置。因此后续 owner 高度操作不能把先前保留的宽行重新裁到当前 61 列，造成 `u/v` 或软续接丢失。
3. 最后恢复宽度后，解码正文、文档/API 标量、marker 和 DSR 与[纯高度样本](../2026-11-02-resize-height-measured-reference/README.md)的恢复阶段相同；初始观测也相同。两次公开件的目录来源/索引元数据仍独立。这只是两条固定轨迹的已观测端点相同，不证明任意宽高操作可交换。

当前 C++ 物理 `Screen::resize(height,currentWidth)` 会按当前列数重新适配已有行，可能丢弃前一宽度保留事务的右尾；这是源码对照，本文没有执行核心回放或声明修复。下一步应以本次精确源、五组 DSR、完整正文和显示位置建立独立字面回放，在同一 owner 内完成高度与宽度保留的组合职责。旧默认路径或已有测试成功不自动满足这条新合同。

仍未知：备用/隐藏帧、非默认 margin/origin、其他光标与底部正文、resize 后写入、历史上限/淘汰、其他尺寸或同时改变双轴、Unicode、选择/Find、真实 Qt/ConPTY 与实际呈现。完整网格、样式、性能及 R2 均未验收。
