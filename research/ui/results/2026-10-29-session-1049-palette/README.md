# 原版会话 1049 阶段的默认颜色与调色板（屏幕捕获）

本片用"合成会话 + 原生注入 + 屏幕捕获"读取原版 2.7.0 在 `1049h` 进入、重复进入与 `1049l` 退出时的**渲染颜色**，作为 [#126](../..#126) 与 [#123](../..#123) 的独立补充证据。它与 #126 合同要求的"应用内 QImage.pixel"是**不同的采集路径**，结论只在本路径与本配置内成立。

## 方法

- 隔离 Windows 11 VM、固定官方 2.7.0 包（EXE 与 4,047 文件身份同其它记录），合成 profile 只有一个会话 `TF_UI_CMD`；
- 会话命令是一个极简原生程序：启用 `ENABLE_VIRTUAL_TERMINAL_PROCESSING` 后按阶段输出纯色块（`SGR0` 空空格、`SGR7` 反显空格、`SGR41/44/42` 背景空格，各 40 列），阶段之间等待外部触发文件；
- 四个阶段：主屏 → `1049h` 备用屏 → `1049l` 后再次 `1049h` → `1049l` 回主屏；
- 宿主在每阶段稳定时通过 QEMU agent 抓取 1024×768 截图；终端内容矩形由 UIA 取得（本次为 [255,196,497,236]），逐行取该矩形内的主导颜色。

## 结果

| 色块 | 含义 | 像素颜色 |
|---|---|---|
| `SGR0` 空格 | 默认背景 | **#1C1C1C** |
| `SGR7` 反显空格 | 默认前景（填成背景） | **#E3E3DD** |
| `SGR41` | 调色板红 | **#C4265E** |
| `SGR44` | 调色板蓝 | **#3465A4** |
| `SGR42` | 调色板绿 | **#86B42B** |

四个阶段（主屏 / alt / 重进 alt / 回主屏）的五行颜色**完全一致**。

阶段确实发生了推进（终端矩形裁切图的 SHA-256 前 16 位）：

| 阶段 | 裁切 SHA-16 |
|---|---|
| 主屏 | `e7dd9042d1ecbb16` |
| alt | `f38a0bcbfe1a2f5e` |
| 重进 alt | `f38a0bcbfe1a2f5e`（与首次 alt 相同） |
| 回主屏 | `d518513bb5fc5040`（内容不同，颜色相同） |


## 附加观察：SGR 属性在 1049 切换前后的保持性

在默认色块之外，另做一组"切换前显式设置 SGR 并保持"的阶段测试，回答"进入/退出备用屏后当前颜色是什么"：

- 会话内原生命令先输出 `SGR 31;44`（红字蓝底），并在切换前**不再 reset**；
- 阶段 M：主屏，重设 31;44 后画"当前背景空格 + 反显空格"；`1049h` 后阶段 A：备用屏同法；`1049l` 后阶段 R：回主屏同法；
- 每阶段外接触发文件同步，逐阶段截图，取终端矩形 [255,196,497,236] 内逐行主导色。

| 阶段 | 当前背景（空格行） | 当前前景（反显行） | 裁切 SHA-16 |
|---|---|---|---|
| M 主屏（31;44） | #3465A4 | #C4265E | `675e5d7b24dbdcf9` |
| A 进入备用屏后 | #3465A4 | #C4265E | `734a58fe0224fcfb` |
| R 退出备用屏后 | #3465A4 | #C4265E | `31a070a2c1706709` |

即：`1049h` / `1049l` **既不重置也不恢复**当前 SGR 属性；三阶段裁切哈希不同、颜色相同，说明阶段确有推进而颜色保持。

**归因边界**：这是 **conhost + ConPTY + WindTerm** 整条管线的可观察渲染；不能据此判定哪一层保持/转发了属性。与 #126 合同要求的应用内 QPainter/QImage 采集不同。


## 附加观察二：备用屏内改 SGR 后退出（M1/A1/M2）

进一步问"备用屏里改了样式，退出主屏后是什么颜色"：

- 阶段 M1：主屏设 `SGR 31;44`，画"当前背景空格 + 反显空格"；
- `1049h` → 阶段 A1：备用屏内设 `SGR 32;45` 同法绘制；
- `1049l` → 阶段 M2：回主屏、**不再设 SGR**，同法绘制。

| 阶段 | 当前背景（空格行） | 当前前景（反显行） | 裁切 SHA-16 |
|---|---|---|---|
| M1 主屏（31;44） | #3465A4 | #C4265E | `c36c54c3ddce39e5` |
| A1 备用屏内（32;45） | #8C6BC8（调色板 45） | #86B42B（调色板 32） | `96deb13c0866d41c` |
| M2 退出后（不重设） | #1C1C1C（默认） | #E3E3DD（默认） | `3c9cd48f2bbc1bf0` |

与本页上一节（进入前设 31;44 并保持，M/A/R 三阶段都是 #3465A4/#C4265E）合起来，得到一致语义：

- `1049h` 进入时**保存**当前属性；
- 备用屏内可任意改 SGR，且**不泄漏**回主屏；
- `1049l` 退出时**恢复进入时刻保存的属性**（上一节进入时是 31;44 → 退出仍 31;44；本节进入前被脚本 reset 成默认 → 退出回到默认）。

**归因边界**：仍是 conhost + ConPTY + WindTerm 整条管线的可观察渲染，无法判定哪一层执行保存/恢复；与 #126 要求的应用内采集不同。


## 附加观察三：三组交叉验证"进入保存 / 退出恢复"

把两组观察再补一组反向用例，形成三组交叉验证：

| 组 | 进入时的属性 | 备用屏内的动作 | 退出后（不重设）的当前属性 | 结论 |
|---|---|---|---|---|
| 1 | 默认（脚本先 reset） | 设为 `32;45` | 默认 `#1C1C1C/#E3E3DD` | 备用屏改动**不泄漏**，恢复进入值 |
| 2 | `31;44`（进入前设置） | 不变 | `#3465A4/#C4265E`（=31;44） | 恢复进入值 |
| 3 | `32;45`（进入前设置） | reset 成默认 | `#8C6BC8/#86B42B`（=32;45） | 恢复进入值，备用屏的 reset 不带走主屏样式 |

第 3 组的三阶段像素：进入前 `#8C6BC8/#86B42B` → 备用屏内 reset 后 `#1C1C1C/#E3E3DD` → 退出后回到 `#8C6BC8/#86B42B`。

三组一致支持同一模型：**`1049h` 保存进入时刻的属性，`1049l` 恢复它**；备用屏内的任何 SGR 变更（设置或 reset）都不会影响主屏退出后的样式。

**归因边界**：conhost + ConPTY + WindTerm 整条管线的可观察渲染；不判定哪一层执行保存/恢复，也不等同于 #126 要求的应用内采集。

## 解释与边界

- 在这套固定配置里，`1049` 的进入/重复进入/退出**不改变**默认前景/背景，也不改变所测的三个调色板颜色；备用屏重进渲染与首次进入一致。
- 采集是**操作系统屏幕捕获**，不是应用内 `QImage::pixel`；不覆盖 ClearType 文本、完整样式、非颜色属性、字体/DPI 差异、其他调色板项或 SGR 变更后的 alt 状态。
- 未测 #126 合同要求的 `isAltScreen/isMainScreen` 调用与 QPainter 颜色；本片不关闭 #126/#123/#27，也不构成原版行为等价声明。
