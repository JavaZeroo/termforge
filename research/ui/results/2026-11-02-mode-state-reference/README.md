# WindTerm 2.7.0：origin 切屏、重复进入与主屏 margin 返回样本

[#27](https://github.com/JavaZeroo/termforge/issues/27) 的三次独立新会话，各固定 14 阶段、一次原版运行。输入直达合成 loopback Telnet，绕开本地 Shell 的 ConPTY/WinPTY 改写。完整输入、DSR、合成文档与 marker 矩形见 [main ON / alt OFF](main-on-alt-off.json)、[main OFF / alt ON](main-off-alt-on.json) 和[重复/再次进入备用屏](alternate-origin-reentry.json)。

## 固定样本的可观察行为

主屏 margin 为 `2..5`，备用屏为不同高度的 `3..7`。每个待测状态先写 marker，再 `CUP(99,1)` 饱和寻址；随后使用同一缓冲区显式 ON/OFF 控制。只看 `CUP(1,1)` 的相对 DSR 无法区分 origin，因此同时核对 marker 文档位置与矩形。

| 样本 | 未显式修改 origin 的观察 | 同缓冲区控制 | 本样本支持的行为 |
|---|---|---|---|
| 两次首次进入备用屏，设置 `3..7r` 后 | 阶段 3 DSR `(20,1)`，`AS` 矩形 y=0 | ON 控制 `(5,1)`、`AI` y=36；OFF 控制 `(20,1)`、`AO` y=0 | 首次进入后的 origin 行为为 OFF |
| main ON → alt OFF → 返回 | 阶段 8 DSR `(4,1)`，`PS` y=18 | ON 控制 `(4,1)`、`PI` y=18；OFF 控制 `(20,1)`、`PO` y=0 | 返回后保持主屏原有 ON 行为 |
| main OFF → alt ON → 返回 | 阶段 8 DSR `(20,1)`，`PS` y=0 | 同上两份可区分控制 | 返回后保持主屏原有 OFF 行为 |

两次刚返回主屏的阶段 7 都回复 `(2,12)`，该回复本身不能区分 origin。上述结论来自后续样本与控制，不是读取内部私有状态位，也不说明原版将状态存在哪个对象。

两次返回后显式 ON 的下界均回复 `(4,1)`；重新铺设 `R01..R08` 后，在该下界执行 `CR LF NW`，前八行依次为 `R01 / R03 / R04 / R05 / NW / R06 / R07 / R08`（main ON 样本的 `MP` 随原 R03 保留）。底行 `SB` 不变，`NW` y=72，DSR `(4,3)`。这支持本次主屏滚动区域 **2..5** 的上下界恢复，没有把同高区域或单条相对坐标当作完整依据。

## 已经 ON 的备用屏重复或再次进入

第三次新会话先明确主屏 origin ON、margin `2..5`，再明确备用屏 origin ON、margin `3..7`。阶段 2 在备用屏内重复 `1049h`；阶段 6 再明确备用屏 ON，阶段 7 退出、阶段 8 再次进入。两个待测样本都只重设同一 `3..7r`、写 marker 和饱和 `CUP(99,1)`，没有隐式发送 `?6h/l`。

| 样本 | 未显式修改 origin 的观察 | 同缓冲区控制 | 本样本支持的行为 |
|---|---|---|---|
| 已为 ON 的备用屏重复 `1049h` | 阶段 3 `(20,1)`，`DS` y=0 | ON 阶段 4 `(5,1)`、`DI` y=36；OFF 阶段 5 `(20,1)`、`DO` y=0 | 重复进入后为 OFF 行为 |
| 备用屏明确 ON → 退出 → 再进入 | 阶段 9 `(20,1)`，`ES` y=0 | ON 阶段 10 `(5,1)`、`EI` y=36；OFF 阶段 11 `(20,1)`、`EO` y=0 | 再次进入后为 OFF 行为 |

阶段 2、8 的未追加寻址 DSR 均为 `(1,1)`；阶段 7、12 返回主屏均为 `(2,12)`。这些回复与后续可区分控制分别保留，不据此断言原版内部的状态对象、位布局或所有模式都被重置。两项新样本不能被简化为“备用屏 ON 状态始终保留”。

## 失败、隐私与边界

此前本机单次启动准备在 `CreateWindowStationW` 返回 `WinError 5`，发生在目标创建之前，未生成 `run.json`，原版启动数为 0。该 attempt、失败日志和当时源码独立保留，没有覆盖或重跑旧计划；这里的三个 VM 样本使用新计划。

[首次/返回探针](../../mode_state_reference.py)与[导出器](../../export_mode_state_reference.py)、[重复进入探针](../../mode_reentry_reference.py)与[独立导出器](../../export_mode_reentry_reference.py)分别保持执行和发布身份。公开 JSON 只包含固定合成输入/文字、DSR、marker 标量、哈希和 Evidence ID；路径、PID、profile、原始资源与完整私有取证记录未发布。三份公开导出另与本地保留的原始 UI 记录逐阶段核对；普通/`-O` 的离线拒绝反例覆盖私有文本、错误身份、partial、case 混用及源/模块变动。第三份离线导出完成后，同一批量导出的外层随后超时；该批次不能标为通过，第三份文件经独立完整性检查后收录，没有因此重跑原版。

原版窗口由自有启动器主动结束，Job 清空不是自然 GUI 退出证明。41/42/43 秒内部期限、45 秒 REA 捕获和 60 秒 CLI 等待均不是整个生命周期的硬上限。文档包含保留主屏内容，不能作为完整 active grid；此次没有样式、resize、真实本地 Shell 运输或性能验收。

三个一次性样本覆盖上述固定 origin 分叉与主屏 margin 返回；其他模式组合、属性、resize 和完整 active grid 仍需各自的证据。本结果不是重复可靠性、完整 #27 或 R2 验收。
