# WindTerm 2.7.0：缩窄后跨前方重排的 CUP 寻址观察

本报告承接 [固定正文三阶段观察](../2026-11-02-resize-state-reference/README.md)、[缩窄后单动作寻址观察](../2026-11-02-resize-address-reference/README.md)及 [ADR-0010 同 owner 正文保留方案](../../../../docs/adr/0010-bounded-resize-retention.md)，服务 #27/#29。既有寻址样本的换行只发生在目标行自身，无法区分"协议行号跟随保留的源片段行"与"跟随当前重排后的显示行"；本切片补上这一缺口。

**结论（有界）**：一次独立原版运行、四个阶段、一个 CUP+Q 动作。原审计与严格导出通过。动作 `CSI 8;2H Q` 写入**保留的源片段行**：Q 文档位置 (逻辑行 6, 列 1)，其所在行与 `6` 同一逻辑行；DSR 为 `8;3`、`caretLine` 为 6，与保留行口径一致。窄屏可见矩形 (155,144) 与恢复后 (155,126) 说明显示层独立重排（前方 123 字符行在窄屏多占一行，后续显示行整体 +1）。因此协议/光标/DSR 寻址层与显示投影层分离，显示行号不能当协议行号。

## 预注册与判读边界

动作与两种竞争解释的独立预期在运行前冻结于[观察协议](../../resize_addressing_reflow_reference.md)（源码基点 `2d27000`），包括：H-source（保留的缩放前 91 列行）预期 Q 在文档行 6、DSR `8;3`、窄屏矩形 (155,144)、恢复 (155,126)、缩窄后动作前 DSR `12;1`；H-display（当前 61 列重排显示）预期 Q 在文档行 5、DSR `7;3`、窄屏 (155,126)、恢复 (155,108)、动作前 DSR `13;1`。严格导出器的有限文本白名单对两种候选目标行都可发布，不预设结论；实际结果由独立 marker/DSR 记录裁决。

## 固定条件

- 固定官方 WindTerm 2.7.0 x64，EXE SHA256 `7b10531dccc7cd614ae559f36f1ef518e0c96335637431b4646354823b2804d0`，完整 4,047 文件清单 SHA256 `e459adf2f12adb6a1b7f55e66a9da1c22794185e66e848057d21e0c60d669203`；直接 Telnet，自有合成 profile 与自有 Job；不指向日常安装目录。
- Windows VM `10.0.26300`，REA `6.7.0`/Frida，Python `3.12.10`。精确窗口 `1360×749 → 1000×749 → 1000×749 → 1360×749`，NAWS `91×20 → 61×20 → 61×20 → 91×20`；高度不变。
- 四阶段各一个 `ESC [ 6 n`；只有阶段 2 追加动作字节 `1b5b383b324851`（`CSI 8;2H Q`）。阶段 0/1 为动作前基线，阶段 3 只恢复宽度。
- 初始正文 222 B：源行 4 起写入 123 字符 `r`×122+`v`（91 列下占源行 4–5，软续接一轮；61 列下占显示行 4–6，使后续显示行 +1），源行 6–10 各写 `5`…`9`，`CSI 12;1H` 把协议光标放到零基行 11。
- 计划只执行一次：`maximum_original_runs=1`、`actual_original_runs=1`；`.attempted` 独占写入，失败保留。

## 直接观察

DSR 为一基协议坐标；文档行/列为零基逻辑行与字符偏移；矩形沿用观测像素 `x,y`（8×18 单元、x=147 原点）。三种坐标分别记录，不互相替代。

| 阶段 | 尺寸/网格 | DSR | Q 文档位置 | v 矩形 | 5…9 所在显示行 |
|---|---|---|---|---|---|
| 0 初始正文 | 1360×749，91×20 | `12;1` | — | (395,90) | 6,7,8,9,10 |
| 1 缩窄后、动作前 | 1000×749，61×20 | `12;1` | — | (147,108) | 7,8,9,10,11 |
| 2 缩窄后 CUP+Q | 1000×749，61×20 | `8;3` | (6,1)，`6Q` | (147,108) | 8,9,10,11,12（Q 在行 8） |
| 3 恢复宽度后 | 1360×749，91×20 | `8;3` | (6,1)，`6Q` | (395,90) | 6,7,8,9,10（Q 在行 7） |

动作后 caret API 为 `caretLine=6, caretPosition=148`（Q position 147 之后）。阶段 1 文档 `line_count` 为 13、阶段 2 为 12、阶段 3 为 11；这里只记录原版 API 返回，不据此推断内部存储或行计数策略。

与预注册预期逐项比较：

| 项 | H-source 预期 | H-display 预期 | 实测 |
|---|---|---|---|
| Q 文档行/列 | (6,1) | (5,1) | **(6,1)** |
| 动作后 DSR | `8;3` | `7;3` | **`8;3`** |
| 窄屏 Q 矩形 | (155,144) | (155,126) | **(155,144)** |
| 恢复后 Q 矩形 | (155,126) | (155,108) | **(155,126)** |
| 缩窄后动作前 DSR | `12;1` | `13;1` | **`12;1`** |

H-display 的每一个可区分预期都被拒绝：若协议行号跟随重排显示，阶段 2 的 Q 应落在 `5` 行并把已有 `9` 的显示行号整体前移；实际 Q 与 `6` 同逻辑行，且显示矩形按独立投影重排。动作前 DSR 在缩窄后仍为 `12;1`，说明光标/DSR 也与保留行一致，而不是随可见行 +1。

## 与工程表示的关系

观测支持现有同 owner 路线：保留源片段的 Cell、身份与软续接不因宽度变化而重排；显示页由独立投影按当前宽度生成；CUP、DSR、caret 继续在保留的源片段/文档位置口径上工作。因此 `Screen::resize_columns_preserving` 之后继续 CUP 写入的映射应是"协议行=保留源片段行、协议列=该行内列"，而不是当前显示行。该结论只覆盖本样本的动作与坐标层，**不**证明原版内部采用相同数据结构，也不证明行号在其它宽度、高度、备用屏、历史或 Unicode 下相同。
