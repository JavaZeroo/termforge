# WindTerm 备用屏 RIS 的光标与滚动区域

2026-11-24 在专用 Windows 11 x64 VM 上，以固定 WindTerm 2.7.0、合成 loopback Telnet 和 `91×25` 网格分别执行两个冻结计划。每个计划各运行一次，自有进程均已回收，专用 VM 显示恢复为 `1024×768`。 [#27](https://github.com/JavaZeroo/termforge/issues/27)

## 取证

初始计划在备用屏 `RIS` 后收到 `13 11 1b 5b 31 3b 31 52`。夹具只接受 DSR，因此未完成该阶段。修订计划保留完整回复，仅在 RIS 阶段允许 DSR 前出现严格的 `13 11`。十阶段严格导出复核了源、实际注入脚本、回复和固定发行物。 [初次失败](first-attempt.json) · [严格导出](validation.json)

| 控制或观察 | WindTerm 观测 |
|---|---|
| 具有历史的主屏和备用屏 | 分别设置 `2..6` 和 `3..7` 滚动区域，两屏配置完成时均回复 `2;7` |
| 备用屏执行 `RIS` | 切回主屏，回复 `1;1`，前有 XOFF/XON 字节 `13 11` |
| 饱和寻址 `CUP 99;1` | 主屏隐式状态与显式开启 DECOM 后均回复 `25;1`，支持主屏滚动区域已恢复全高 |
| 随后显式 `1049l` | 回复 `3;7`，与 RIS 刚完成时的 `1;1` 分列 |
| 再次进入备用屏 | 回复 `1;1`，开启 DECOM 并饱和寻址后回复 `25;1` |
| 最后的主屏 RIS 对照 | 回复 `1;1`，前有同一对 `13 11` |

公开文档在重置后仍可找到 `HIST`、`MAIN`、`ALT`，重置后写入的 `AFTER` 未从本次文档读取路径观测到。该 API 混合保留内容，活动网格与历史归并规则仍需独立验证。再次进入备用屏后的满高也可能由 `1049h` 生效，现有阶段无法区分其独立作用。

## TermForge 回放

旧核心在备用屏 RIS 后立即报告 `3;7`，并在重新开启 DECOM 后仍受主屏旧边界约束。核心已修正这条路径返回时的主屏光标归位与全高滚动区域。字面回放覆盖前五阶段、严格与恢复解析、整段与逐字节输入。后续显式 `1049l` 的保存光标、文档保留策略及正式 Qt／固定 ConPTY 联合验证仍待收口。 [核心回放](../../../../experiments/core/alternate_mode_test.cpp)
