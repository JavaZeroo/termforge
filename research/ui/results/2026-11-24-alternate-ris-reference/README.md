# WindTerm 备用屏 RIS 的光标与滚动区域

2026-11-24 在专用 Windows 11 x64 VM 上，以固定 WindTerm 2.7.0、合成 loopback Telnet 和 `91×25` 网格分别执行两个冻结计划。每个计划各运行一次，自有进程均已回收，专用 VM 显示恢复为 `1024×768`。 [#27](https://github.com/JavaZeroo/termforge/issues/27)

## 取证

初始计划在备用屏 `RIS` 后收到 `13 11 1b 5b 31 3b 31 52`。夹具只接受 DSR，因此未完成该阶段。修订计划保留完整回复，仅在 RIS 阶段允许 DSR 前出现严格的 `13 11`。十阶段严格导出复核了源、实际注入脚本、回复和固定发行物。 [初次失败](first-attempt.json) · [严格导出](validation.json)

| 控制或观察 | WindTerm 观测 |
|---|---|
| 具有历史的主屏和备用屏 | 分别设置 `2..6` 和 `3..7` 滚动区域，两屏配置完成时均回复 `2;7` |
| 备用屏执行 `RIS` | 切回主屏，回复 `1;1`，前有 XOFF/XON 字节 `13 11` |
| 饱和寻址 `CUP 99;1` | 主屏隐式状态与显式开启 DECOM 后均回复 `25;1`，支持主屏滚动区域已恢复全高 |
| 随后显式 `1049l` | 回复 `3;7`，与 RIS 刚完成时的 `1;1` 分列 |
| 再次进入备用屏 | 回复 `1;1`，开启 DECOM 并饱和寻址后回复 `25;1` |
| 最后的主屏 RIS 对照 | 回复 `1;1`，前有同一对 `13 11` |

公开文档在重置后仍可找到 `HIST`、`MAIN`、`ALT`，重置后写入的 `AFTER` 未从本次文档读取路径观测到。该 API 混合保留内容，活动网格与历史归并规则仍需独立验证。再次进入备用屏后的满高也可能由 `1049h` 生效，现有阶段无法区分其独立作用。

## TermForge 回放

旧核心在备用屏 RIS 后立即报告 `3;7`，并在重新开启 DECOM 后仍受主屏旧边界约束。第一轮核心修正覆盖切回主屏时归位与全高滚动区域，字面回放覆盖前五阶段。显式 `1049l` 和复入备用屏由后续独立对照验证。 [核心回放](../../../../experiments/core/alternate_mode_test.cpp)

## 显式返回与备用屏重新进入（2026-11-25）

同一隔离 Windows 11 VM、固定 WindTerm 2.7.0 和 `91×25` loopback Telnet 网格，用独立的 14 阶段计划运行一次。严格导出复核冻结输入、回复和发行物身份。内外 Job 活动进程均归零，VM 显示恢复 `1024×768`。 [阶段输入、完整回复与身份](follow-up-20261125.json)

| 对照动作 | DSR 观测 |
|---|---|
| 普通 `1049l` 后在主屏移动，再发一次 `1049l` | 保持 `10;11` |
| 无 RIS，带旧 `3..7` 备用屏区域，退出后重新进入，再开启 DECOM 饱和寻址 | `25;1` |
| 备用屏 RIS 与随后主屏饱和寻址 | `1;1`（前缀 `13 11`），随后 `25;1` |
| 首次、第二次显式 `1049l` | 首次恢复 RIS 前主屏绝对光标 `3;7`；第二次保持新位置 `9;11` |
| RIS 后重新进入备用屏再饱和寻址 | `25;1` |
| 主屏 RIS 后移动，再发 `1049l` | 保持 `8;10` |

核心用独立字面轨迹覆盖两批观测。在旧实现上，首批第 5 阶段仍返回 `25;1`。修复后，备用屏 RIS 保留一次显式恢复的旧主屏光标，实际从主屏进入备用屏时使用全高区域。两个轨迹共 24 个阶段，在 strict/recovery、整段/逐字节四种组合下通过 96 个阶段。原版线上的 `13 11` 保留在证据中，核心回放独立校验 DSR。 [回放测试](../../../../experiments/core/alternate_mode_test.cpp)

该取证区分了退出再进入和 RIS 两条路径；连续在已活动备用屏发送 `1049h` 的区域副作用、保存光标与 resize 交叉、文档归并及正式 Qt／固定 ConPTY 联合验证仍待独立观测。
