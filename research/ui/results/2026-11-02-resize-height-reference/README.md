# WindTerm 2.7.0：高度预测失败，初始夹具有效

固定 `height-only` 样本执行一次，完成初始阶段后在第一次缩高时停止：请求窗口 `1360×569` 后，NAWS 实测为 **91×14**，没有达到冻结计划要求的 **91×10**。这份[失败摘要](failure-observation.json)保留已有观察与缺失字段，**不是原严格成功导出器的通过结果**。`width-then-height` 尚未启动，原版运行次数为 0。

## 原计划与实际边界

运行源码基点 `cf58f30f77a83478361b5091b9856cbbf00fda3e`；10 个执行源、3 个离线导出源和归档清单的字节已与冻结 ZIP 核对。原计划、失败记录均保留，没有重放计划或修改冻结源码。

- 原计划 SHA256：`02b86050bb5956137be6eb9d1ef8a8edb05e16034479f70de51267e5cdb8f877`。
- 源码 ZIP SHA256：`472b5754910c078b55ccfd7551fa7b8c1ddbbaba843643492606389ca2fadad4`。
- 执行源 manifest SHA256：`07fef89910bba0eee86a3daa1385481c2de1bd07c9779d3544ba0a7254d6ba28`。
- 计划请求 `1360×749 → 1360×569 → 1360×749`，要求 NAWS `91×20 → 91×10 → 91×20`。569 是此前按十行、每行 18 px 推出的未验证预测。
- 源码重建的注入脚本 SHA 与 run/provider 记录一致；provider 记录中的唯一正文阶段及失败结果与下载原件完全相同。

控制器在 `fixed resized grid differs` 处先抛错，尚未执行该阶段的 `checkWindow`。因此不能声称实际窗口就是 569 px，也不能据此断定最小窗口高度、布局或 splitter 是原因。没有缩高后的正文、marker 矩形、光标或恢复高度样本，不能判断原版高度保留/滚动策略。

## 失败与审计范围

拥有进程的请求返回 exit 1/status failed，`RootReaped=true`、`CleanupVerified=true`、JobAfterActive=0；启动器 Job 另记 active=0/total=3/terminated=0。清理完成不把失败变成语义通过，也不证明自然 GUI 退出。合成会话检查记录为唯一会话。

本地审计复核完整 4,047 条包清单的规范哈希与记录中的原版身份，但没有在本地重新读取原版包/执行副本，也没有下载实际 `probe.js`；脚本身份由冻结源码重建并与 run/provider SHA 对比。不得将这份局部失败摘要写成完整原包重新审计或原严格成功导出。所有私有路径、PID、会话文件与原始 provider 元数据保留本地，仅公开合成正文、标量和哈希。

下一步先用独立新计划调查请求窗口、实际窗口、实际 NAWS/capacity 及终端区域几何的配对。不得把本样本的预期 10 行改成 14 行后重跑取绿；在实际高度边界查明之前，组合尺寸样本与核心高度实现仍待调查。
