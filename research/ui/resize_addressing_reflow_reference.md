# 缩窄后跨前方重排的 CUP 寻址独立原版观察协议

本文件为 **运行前冻结** 的观察合同：先固定"能区分竞争解释的动作与独立预期"，再对固定 WindTerm 2.7.0 取证一次；失败保留、不重跑、不改断言。承接 [三阶段正文保留观察](results/2026-11-02-resize-state-reference/README.md) 与 [缩窄后单动作寻址观察](results/2026-11-02-resize-address-reference/README.md)，服务 #27/#29 与 [ADR-0010](../../docs/adr/0010-bounded-resize-retention.md)。本文件不是原版运行结果；正文中的"预期"是假设，不是用当前实现充当 oracle。

## 为什么需要新样本

已有寻址样本的正文只有**目标行自身**换行（`w/x` 位于底部逻辑行），行号层面"保留的源片段行"与"重排后的显示行"恰好同为第 11 行，因此只能区分列映射，不能区分行映射。若缩窄使**前方行**多占一行显示行，后续行的显示行号整体 +1，而保留的源片段行号不变，两种解释才会给出不同目标：

| 解释 | CUP 行/列作用域 |
|---|---|
| **H-source（保留源片段/缩放前 91 列行网格）** | 协议行=保留源片段行，协议列=该行内列 |
| **H-display（当前 61 列重排后的显示网格）** | 协议行=当前显示行，协议列=该显示行内列 |

## 固定条件

- 固定官方 WindTerm 2.7.0 x64（EXE SHA256 `7b10531dccc7cd614ae559f36f1ef518e0c96335637431b4646354823b2804d0`，完整 4,047 文件清单 SHA256 `e459adf2f12adb6a1b7f55e66a9da1c22794185e66e848057d21e0c60d669203`），直接 Telnet，自有合成 profile 与自有 Job；不指向日常安装目录。
- 窗口 `1360×749 → 1000×749 → 1000×749 → 1360×749`，NAWS `91×20 → 61×20 → 61×20 → 91×20`；高度不变。初始与 resize 冻结沿用连续 600 ms 稳定网格，单阶段观察沿用连续 400 ms 快照稳定。
- 四阶段，每阶段末尾恰一个 `ESC [ 6 n` DSR 请求；**只有阶段 2** 有额外动作，字节精确为 `1b 5b 38 3b 32 48 51`（`CSI 8;2H Q`）。阶段 0/1 是动作前基线，阶段 3 只恢复宽度。
- 每 case 一个新计划、一个新原版进程、期计划最多一次执行；执行前独占写 `.attempted`，失败保留。

## 固定正文与已知几何

初始正文（91×20）在同一份字节中写入：

| 源行(0基) | 内容 | 说明 |
|---|---|---|
| 1 | `0123456789` | 稳定性 marker |
| 2 | `ANCHOR` | 稳定性 marker |
| 4 | `r`×122 + `v` | **前方重排行**：91 列时占源行 4–5（逻辑行 123 字符，软续接一轮）；61 列时占显示行 4–6，因此后续显示行全部 +1 |
| 6 | `5` | 目标候选行（H-source 行号与 H-display 行号错位） |
| 7 | `6` | 目标候选行 |
| 8 | `7` | 目标候选行 |
| 9 | `8` | 目标候选行 |
| 10 | `9` | 目标候选行 |
| 11 | 空 | 用 `CSI 12;1H` 把协议光标放这里 |

`v` 是重排行的末字符，宽屏显示位置 (395,90)（行 5、列 31），窄屏 (147,108)（行 6、列 0）；两者差一行，正是"前方重排"的可观测证据。正文不含样式、Unicode、备用屏或历史操作。

## 竞争解释的独立预期（运行前固定）

动作 `CSI 8;2H Q` 把 Q 写到协议第 8 行、第 2 列。窄屏重排后：

| 可观测项 | H-source 预期 | H-display 预期 |
|---|---|---|
| 动作后 Q 所在文档逻辑行/列 | 行 6（`6` 行）、列 1 → 该行变 `6Q` | 行 5（`5` 行）、列 1 → 该行变 `5Q` |
| 动作后 DSR（源片段口径 +1） | `8;3` | `7;3` |
| 窄屏 Q 可见矩形左上角 | (155,144)（显示行 8，列 1） | (155,126)（显示行 7，列 1） |
| 恢复 91 列后 Q 可见矩形 | (155,126)（显示行 7） | (155,108)（显示行 6） |
| 阶段 1（只缩窄、动作前）DSR | `12;1`（源片段行 11 +1） | `13;1`（显示行 12 +1） |

说明：H-source/H-display 是行号作用域的两种极端；DSR 自身也可能与寻址层不同源（`8;3` 在"源寻址+源 DSR"与"显示寻址+显示 DSR"下巧合相同，`9;3`/`7;3` 才分别表示混合口径）。因此**唯一裁决项是 Q 落在 `6` 行还是 `5` 行**（文档行列、marker 与矩形三处独立记录），DSR 与 caret 作为交叉核对，不单独判定。

其余在两种解释下相同的预期：

| marker | 文档位置 | 宽屏矩形 | 窄屏矩形 |
|---|---|---|---|
| `0123456789` | 行 1，列 0…9 | y=18 | y=18 |
| `ANCHOR` | 行 2，列 0 | y=36 | y=36 |
| `v` | 行 4，列 122 | (395,90) | (147,108) |
| `5`/`6`/`7`/`8`/`9` | 行 5/6/7/8/9，列 0 | 宽屏 y=108/126/144/162/180 | 窄屏 y=126/144/162/180/198 |

阶段 3 恢复 91 列后，`v` 与数字行应回到宽屏矩形；Q 保留在动作后所在文档位置。以上矩形基于已知 8×18 单元网格与 x=147 原点，沿用同一像素口径，不是完整 grid。

## 判读边界

- 任一白名单外文本、错误尺寸/网格、未武装 NAWS、过期快照、动作前缺 ack、额外回复或超界均失败；失败原件保留，不改断言、不重跑、不静默放宽。
- 显示行号不能直接当协议行号；本样本只裁决上表动作目标，不证明内部存储结构，也不证明行号在其它宽度/高度/备用屏/历史/Unicode 下相同。
- 观察结果与核心实现不一致时，保留 RED，再修复或如实记录差异；一致时只交付补齐的证据与门禁，不制造生产改动。
- 本切片不豁免 Qt/固定 ConPTY 的用户路径缺口，不关闭 #27/#29，不声明完整 reflow、WindTerm 等价或性能结果。
