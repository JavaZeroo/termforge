# 工作区 DPI 与会话文字缩放

固定起点：`1a3e3dfb5fbadf975450298dac5e8cfe25bd9e8e`。继续完善 UI 显示、终端网格与 DPI；原有 96 逻辑单位布局及两区域会话行为保持可回归。

## 交付与验收

- 每个会话独立支持文字缩放 50%–200%，每次 25%；当前区域的 `Ctrl++` / `Ctrl+-` / `Ctrl+0` 和 View 菜单执行放大、缩小、重置。其他会话不随之改变，标签切换保留各自比例；重命名期间快捷键留给编辑器。
- Renderer 将字号、文字位置、裁剪、光标和整数物理网格使用同一组度量。96 DPI / 100% 保留 12×26；任意支持缩放下网格边界均为单元物理尺寸的整数倍，避免逐列累计舍入差异。
- 字体/DPI 改变后重新布局并全量更新保留位图，即使行列数没有变化。核心与 ConPTY 按新物理单元尺寸计算行列，仍使用已有物理行 resize 契约，不引入 reflow。
- 工作区在启动时读取窗口 DPI，处理 `WM_DPICHANGED` 的建议外框；逻辑布局、物理子窗口位置、字体、命中、分隔线、菜单位置和重命名编辑器一起缩放。变化传播到隐藏会话。保存比例而非显示器 DPI。
- DPI 切换期间取消未提交的拖动，保留重命名内容和键盘焦点。字体替换完成后再释放旧资源，当前会话关闭过程不被新输入/缩放打断。
- 自动场景使用自有非输入桌面，在 96→144→192→96 的受控消息切换中验证两区域和隐藏会话、实际 HWND/子进程尺寸、缩放隔离、鼠标命中、编辑器、布局恢复和进程回收；Renderer 单独验证非整数缩放下 dirty/full 位图、光标和字体审计。
- 非整数 DPI / 非整除客户区也必须覆盖实际窗口右侧和底部边缘，子窗口贴边与命中使用同一物理端点；补充 168 DPI / 2001×1406 的边界回归。

## 证据边界

测试分别记录请求的受控 DPI 与系统 `GetDpiForWindow` 返回值。发送受控 `WM_DPICHANGED` 不等于实际切换显示器或修改系统显示设置。终端继续使用既有字体族，只改变可调字号和网格；不声称与 WindTerm 字形/逐字形 fallback、实际呈现时延或性能等价。缩窄仍可能裁掉内容；缩放比例暂仅保留在会话生命周期内。
