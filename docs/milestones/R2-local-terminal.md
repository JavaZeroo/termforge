# R2 本地终端与开发版出口检查表

本文件细化 [PLAN 的 R2 出口](../PLAN.md#r2可靠本地终端持久化与可发布开发版)，不改变原范围。当前能力只在 [FEATURES](../FEATURES.md) 维护，执行状态与阻塞以 [总项 #7](https://github.com/JavaZeroo/termforge/issues/7) 及原生子项为准；这里不按关闭数量计算完成率，也不累计开发批次。

用户结果：在明确支持的 Windows 环境中，用固定本地 shell、分页器和编辑器完成连续工作；复杂文字、输入和会话互相一致；重启后恢复已声明的配置；最终下载包能从公开源码复建。

## 必须闭合的验收门槛

| 门槛与责任项 | 验收必须证明什么 | 不能代替验收的结果 |
|---|---|---|
| 回归可靠性：#36、#38（含 #40、#44） | 持续输出中断、controller 子进程到 shell 的正常退出、原 10 秒纯夹具失败路径均有明确阶段、字节、退出和自有 Job 回收证据；修复对应真实失败，最终声明配置的完整回归通过 | 多次重跑绿不能回填旧失败原因；close 后的退出码不能冒充自然退出；增加超时或跳过不能解除阻塞 |
| 终端模式：#27、#41 | 候选核心主/备用屏、各自滚动区域、origin/wrap、光标/样式、历史隔离及 resize 交叉符合固定合同；真实 ConPTY 路径保留实现这些语义所需的信息 | 独立核心 feed 正确不能补足宿主已经丢失的信息；不能猜测补发原运输中不存在的 VT，或用“已知平台差异”自行关闭功能缺口 |
| resize 与真实 TUI：#29、#28 | 逻辑/物理行、宽字符、历史与淘汰有明确策略；窗口、核心和真实子进程尺寸一致；固定应用逐一完成进入、操作、resize、退出、主屏恢复；回复、输入模式和 bracketed paste 字节经独立预期验证 | 离线回放、单独 Vim 成功或默认核心通过，不能代表整个候选产品矩阵；未声明应用不计完成 |
| 复杂文字与输入：#30、#39 | 首批 ZWJ/keycap 等样本有明确聚类、宽度、光标和选择合同，覆盖分块/样式/resize/历史边界；原始标量、实际 glyph、复制和子进程接收分别核对；固定 IME 与八会话回归保留 | 原文没丢、glyph 非零或逐标量宽度正确，不能证明字素聚类成立；未知 WindTerm 行为继续明确保留 |
| 真实显示：#31 | 按[字体/显示合同](R2-font-display.md)记录实际不同 DPI、真实跨屏、焦点、IME/Find/rename、命中、隐藏会话及子进程尺寸；环境身份和重复结果可核对 | 相同 96 DPI 的两台显示器、受控消息、DIB 或实际提交时刻不能代替不同 DPI 或实际上屏证据；不得修改个人显示设置制造验收 |
| 产品架构：#34 | 基于上述实际工作流与 #23/#26、已验收的 #32/#33，重审 ADR-0004；明确产品核心选择、GUI/平台边界、历史/快照、传输/呈现、背压/取消、依赖升级与维护策略 | 原型已采用某技术或候选已有接口，不构成最终产品选择；未测性能仍保持未知 |
| 开发版交付：#35 | 最终下载产物通过干净构建、依赖/字体许可和清单审计、解压运行、shell/TUI/文字/配置升级/真实显示工作流；按预先冻结的负载和资源合同完成重复会话与持续运行，逐项核对本表 | Alpha 1、源码构建成功、短驻留或某一 CI 通过，不代表 R2 日常开发包、长期稳定或 WindTerm 性能等价 |

#32 本地 shell/分屏标签、#33 会话与配置恢复已有各自限定合同；最终集成仍须复验这些合同。R2 不扩大为 SSH/SFTP、任意嵌套分屏、完整 WindTerm UI 或跨平台客户端；这些任务继续按 PLAN 的对应路标推进。

## 最近的工作顺序

前三项不互相依赖，可在独立工作树并行诊断；每项形成独立可审查的 PR。遇到暂时不能复现的历史问题，提交可定位性改进时明确保留原问题，不阻塞其他独立工作。

1. **#44：区分自然退出与清理。** 在原退出期限内记录发送结果、wait_exit 布尔、close 前状态及 close 后结果；先用受监督原场景复现，再比较子进程结束、shell 返回与输入交接的时序。必要握手须证明作用于同一类失败，不能靠额外等待预算取绿。
2. **#40：把超时落到具体阶段。** 分别记录进程启动、AST、被测失败路径和最终进度；即使原 10 秒到期也保留已完成阶段及回收。固定源码的本机与 CI 证据分列；仅诊断改进不能关闭历史根因。
3. **#41：确认后端能否保留必要信息。** 先重放原 source/原生控制台/transport，再核对受支持的模式或后端；每种方案记录 API、版本、许可、部署边界和反例。若信息不可恢复，明确后端/上游工作，而不是在呈现层猜补状态。
4. **合并终端行为验收。** #41 的可行路径明确后补齐 #27 的 origin/wrap、区域与 resize；与 #29 联合回归后，由 #28 验收固定 TUI、回复、应用键盘和粘贴。共同内容可提前做独立实现和测试，联合出口仍按依赖验收。
5. **复杂文字与真实显示并行。** #39 先冻结可维护的流式分段合同及依赖，再实现 #30 的完整输入/选择流程。#31 独立准备实际不同 DPI 的受控测试环境；环境缺口保持开放。
6. **完成架构与开发包。** #34 使用前述结果作决定；#35 在最终发行物上执行全部合同和持续运行。运行前冻结时长、会话数、负载、动作、采样与资源预算，不根据结果反填门槛。

## 证据与完成规则

- 每个结果保留源码/二进制、系统/后端、输入/负载身份，以及实际通过、失败和跳过；不同源码或补充运行不拼成一次“全绿”。
- 控制台、模型、DWrite 布局、DIB、窗口提交和实际呈现各自留证；未观测端点保持 unknown/null。
- 只公开经审核的合成输入和脱敏摘要；运输原件、用户路径、桌面身份等按现有来源规则处理。所有无人值守进程在自有 Job 中启动、超时和回收。
- 单项完成更新其 issue、FEATURES 与 EVIDENCE；原失败仍保留。若真实平台能力迫使改变合同，先明确提出范围/架构决定，不能用新合同证明旧合同已完成。
- #7 由 #35 对所有出口逐项核对后结项；正式 WindTerm 性能基线继续独立推进，不由本表推断已经等价。
