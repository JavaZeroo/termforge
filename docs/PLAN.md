# 总体实施计划

## 目标

完整开源、可维护，在主要日常场景中达到 WindTerm 的性能和体验。技术栈不是预设答案，通过正确性、性能与维护成本共同决定。历史上的“优先 Electron/现有客户端扩展”建议已经被这个决策取代。

## 执行顺序与关卡

| 阶段 | 工作 | 交付物 | 通过条件 |
|---|---|---|---|
| 目标定义 | 必需场景、平台和功能优先级 | 功能矩阵、指标定义 | 目标可测量且边界清晰 |
| M0 基线 | 固定输入、受控环境、重复测试 | 工具、原始样本、基线报告、原型规格 | 结果可复现，测量误差和正确性已说明 |
| M1 原型 | 接收→解析→屏幕/历史→布局→呈现，输入回路 | 最小可运行核心、逐层计量、候选实验 | 可定位成本，关键终端行为正确 |
| M2 性能 | 数据布局、分配、复制、刷新、缓存、背压 | 对照结果与选型 ADR | 达到 M0 后设定的多维预算，无隐藏功能退化 |
| M3 日常使用 | SSH/SFTP、本地终端、会话、分屏、凭据、安装 | 可日常使用的开发版 | 真实任务、异常恢复和持续运行通过 |
| M4 扩展发布 | 高级文本/协议功能、跨平台、发布流程 | 支持矩阵、公开构建、回归体系 | 声明支持的功能/平台均有证据 |

## 工作流

当前执行切片以[现状与任务拆解](STATUS-AND-BACKLOG.md)为准：E1/C1/T1/C2/V1 已完成受限验收，A1/C5 已连接可缩放本地 shell 并完成 G1 基础闭环。按用户最新优先级，先做 [UI-A/B/C 对齐](research/windterm-ui-2026-10-23.md)：发行物/二进制/隔离运行时取证，再独立实现布局、真实多标签与自动对齐回归。首轮取证、UI-A 初始布局/真实底部多标签及 UI-B 拖动/重命名/布局恢复切片已交付；下一步补测字体/DPI、已有主连接标签及动作上下文，扩展 UI-C 几何与交互回归。C3/C4 状态兼容性、U1 基础输入与性能分层继续保留，不把外观对齐视为 G2 或性能达标。

2026-10-22 起按 [ADR-0002](adr/0002-automation-first-investigation.md) 调整：默认由代理自动执行，M0 调查与 M1 小型原型交替推进。完整基线不再阻塞原型启动，但仍是正式性能达标判断所需的证据。停止扩展要求用户反复新建标签页、执行命令、输入确认的测试路线。

无界面定向分析和有限核心实验已完成首轮；WindTerm 自动会话仍做有限探针，作为性能证据支线。探针不可行时记录缺口并继续自有原型，不转交用户重复操作。尚未实现的自动化不视为已有能力。

性能工程与正确性验证贯穿所有阶段。研究只回答具体问题，不以恢复私有源码作为前置条件。产品整合在核心约束明确后扩展；不提前建设大而无法测量的 UI 框架。

关键设计实验包括：普通文本快路径与控制序列解析、块式历史和紧凑属性表示、可见区域布局/绘制、压缩与缓存成本、更新合并及延迟、多会话公平调度、后台搜索和任务取消。它们是待验证的假设，不是已经确定的实现。

## 维护的四份材料

1. 功能矩阵：实现状态、优先级、已知差异。
2. 性能基线：环境、样本、正确性、统计与限制。
3. 架构决策：候选、实验、取舍和重审条件。
4. 已知差异：协议兼容、平台、行为和性能缺口。

## 时间与范围

M0 完成前不承诺整个项目工期。根据基线与原型结果拆分后续任务。完整开源意味着独立可构建，不意味着第一版一次性交付所有 WindTerm 功能。
