# 工作区 DPI 与会话文字缩放审查

固定起点：`1a3e3dfb5fbadf975450298dac5e8cfe25bd9e8e`。需求见 [UI-dpi-zoom](../milestones/UI-dpi-zoom.md)。Standards / Spec 由独立代理只读审查，实施代理运行实际构建和测试；未重新提取或复制 WindTerm 资源。

## Standards

审查发现并修正一项 P2：为避免 DPI 更新期间同步绘制旧画布，子窗口改用 `MoveWindow(FALSE)`，但不足一个字符格的几何变化不触发网格 resize，可能遗漏窗口重绘。现在布局同步后显式无擦除失效子窗口；自动场景清空更新区域、将宽度增加 1 像素，确认网格未变而更新区域重新产生。独立复审确认关闭。

实施中发现并修正 DPI 的中间尺寸裁剪：在旧窗口像素尺寸上先套新字号会短暂缩小核心网格，长行不可恢复。现在先更新度量并延迟网格 resize，再按最终子窗口尺寸提交；隐藏标签的 101 字符完整行验证该边界。

另补强帧验收：先核对保留位图确实具有当前网格的物理尺寸，再与全量重绘比较，避免两张同样过小的画布误报一致。144 DPI 切换后、下一条命令输出前即检查隐藏和可见会话，确保新输出不会掩盖旧画布问题。关闭场景在缩放请求后立即关闭，再调用 DPI / zoom 操作，验证关闭期间忽略变更和进程回收。

## Spec

独立审查核对 50%–200% / 25% 步长、当前区域快捷键、每会话隔离、隐藏标签传播、编辑器字体/内容/焦点、拖动取消、子进程尺寸查询，以及实际系统 DPI 和受控 DPI 的区分。

发现并修正一项 P2：168 DPI、客户区 2001×1406 时，逻辑尺寸舍入后再换回像素仅为 2000×1405，右侧/底部一像素可能漏绘。矩形贴边端点现在锚定实际物理客户区，命中使用同一逆映射；场景验证子窗口贴边、末端命中，以及预填哨兵色后所有右/下边缘均被覆盖。独立复审确认关闭，无剩余发现。
