# ADR-0008：自主 C++ 核心与当前 Qt Widgets GUI 路线

- 状态：已确认路线；实现与验收未完成
- 日期：2026-10-28
- 决策者：项目负责人（用户）
- 确认依据：在比较自主核心、Alacritty、其他开源核心及 WindTerm 原版方案后，用户明确“继续自主开发 C++ 核心”；对上一轮 Qt Widgets GUI 建议确认“这个可以先用你推荐的来”。后一句确认当前采用 Qt Widgets，未将具体版本或渲染策略永久锁定。

正式产品继续自主开发 C++ 终端核心，按 WindTerm 2.7.0 的实际行为独立实现，并研究、借鉴许可明确的公开代码与原版机制。当前 GUI 路线采用 Qt Widgets，终端绘制与核心、历史、传输分别可测；Windows 本地 Shell 后端沿用 [ADR-0007](0007-bundled-microsoft-conpty.md) 已确认的随包固定微软 ConPTY。

## 取舍与已有成果

自主核心由本项目承担完整终端语义、文字、历史、回复和兼容维护，以便围绕固定原版目标控制实现。当前 C++ 核心仍是有限子集，不因本次选型获得 Alacritty 已验的备用屏、字素或 TUI 能力；按实际缺口逐项实现和复验。

Qt Widgets 提供窗口、控件和布局基础，便于推进完整桌面 UI 与最终跨平台目标；迁移现有 Win32 UI 有实际成本。原版包及[运行观察](../research/windterm-ui-typography-2026-10-23.md)确认 Qt Widgets、定制文本控件和部分 QPainter 路径，但不证明我们的 Qt 实现自然达到原版正确性或性能。

Alacritty 的候选代码、补丁、差分轨迹及各次结果保留为参考，不再作为正式产品核心扩展。已有 Win32/DirectWrite/Direct2D、默认 C++/系统 ConPTY、候选/实验后端构建与 Alpha 保留各自来源和历史状态；它们的成功不能拼成 C++/Qt/固定 ConPTY 新配置的验收。

## 实施边界

- 先建立可构建、可观测的 C++/Qt 最小入口并复用固定 ConPTY 接入，再按真实缺口补终端基础、历史、输入和 TUI；不先搭建大型应用骨架。
- Qt 的具体版本、终端控件绘制策略、线程调度及缓存由工程证据决定并固定身份；引入新的重大依赖、改变范围或替换当前路线仍提交用户确认。当前采用 Qt 不批准任何未测性能排名。
- 原版行为优先继续生效。未知行为保持调查项；重要差异或原版缺陷修正单独确认。不得为了沿用旧测试而静默接受不符合原版的行为。
- 性能保持正确性、交互延迟、吞吐、CPU、内存及公平性分别测量。数值容差仍在可靠基线后与用户明确；本决定没有批准百分比门槛。
- [#34](https://github.com/JavaZeroo/termforge/issues/34) 接续接口、迁移、支持配置与证据收敛，[R2 出口](../milestones/R2-local-terminal.md)和各责任 issue 继续维护验收。本次路线确认不关闭 #34、R2 或任何真实功能缺口。
