# ADR-0001：性能证据先于技术栈

- 状态：接受
- 日期：2026-10-19

## 背景

项目需要接近 WindTerm 的速度和资源效率，同时易于维护。仅凭语言、GUI 框架或渲染 API 无法预测完整应用表现。早期考虑的现成客户端/Electron 路线尚未进行性能验证，不能作为已定方案。

## 决策

先完成基准规范、WindTerm 实测和瓶颈假设，再通过小型完整数据路径原型选择架构。C++/Qt、其他原生实现或复用现有终端引擎均可作为候选；不为候选建设完整客户端。

必须同时评估终端正确性、输入延迟、吞吐、内存、CPU、多会话稳定性以及工程维护成本。每项选择记录实验和代价，不以一个微基准作全局结论。

## 后果与重审

短期交付以测量工具和规格为主，应用功能启动较晚，但避免围绕错误假设积累大量代码。M0/M1 结束后用新的 ADR 固定首个实现方案；重大负载变化或回归可以触发重审。
