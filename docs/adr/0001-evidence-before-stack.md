# ADR-0001：性能证据先于技术栈

- 状态：证据原则由 [ADR-0006](0006-confirmed-project-direction.md) 确认；原型执行顺序由 [ADR-0002](0002-automation-first-investigation.md) 修订，具体栈与性能容差仍待用户确认
- 日期：2026-10-19

## 背景

项目以 WindTerm 2.7.0 关键指标达到同等性能水平为目标，同时易于维护；允许波动范围在可靠基线后与用户明确。仅凭语言、GUI 框架或渲染 API 无法预测完整应用表现。早期考虑的现成客户端/Electron 路线尚未进行性能验证，不能作为已定方案。

## 决策

先完成基准规范、WindTerm 实测和瓶颈假设，再通过小型完整数据路径原型选择架构。C++/Qt、其他原生实现或复用现有终端引擎均可作为候选；不为候选建设完整客户端。

必须同时评估终端正确性、输入延迟、吞吐、内存、CPU、多会话稳定性以及工程维护成本。每项选择记录实验和代价，不以一个微基准作全局结论。

## 后果与重审

本 ADR 最初要求先完整测量再启动应用；该顺序已由 ADR-0002 修订为自动调查与独立原型并行。当前按 R1–R5 推进，先对齐终端基础能力与性能；主要技术路线和性能门槛按 ADR-0006 提交证据供用户确认。历史 M0/M1 名称及早期候选保留原义，不构成现行选型。
