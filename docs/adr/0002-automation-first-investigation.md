# ADR-0002：自动执行优先，研究与原型交替推进

> 本决策继续有效。当前能力见 [FEATURES](../FEATURES.md)，任务见 [TRACKING](../TRACKING.md)；旧工作包与工具安装过程见[历史版本](https://github.com/JavaZeroo/termforge/blob/c386494587656faa3d8621f7ddbf43a6aa678255/docs/adr/0002-automation-first-investigation.md)。本页只维护决策和执行约束。

- 状态：自动执行原则保持接受；重大决定的确认权限由 [ADR-0006](0006-confirmed-project-direction.md) 明确
- 日期：2026-10-22
- 修订 ADR-0001 的执行顺序，保留其性能证据与正确性要求。

## 背景

用户明确要求尽量全自动工作，不再把重复测试交给用户。现有 WindTerm 诊断依赖手动开关标签、粘贴命令和确认标记，已成为推进障碍。工具功能齐全并不意味着研究取得足够进展。

现有烟测验证了生产/采样链路和人工可见标记。12 步诊断在 5 步后由用户结束，包含 2 次预热和 3 次对照；保留原始数据，不补造确认或样本。没有完成正式采样开销校准或性能等价验证。

## 决策

1. 默认交付可由代理执行的 CLI、脚本或测试。测试循环不要求用户新建会话、输入 y、复制结果或确认每一轮。仅确实需要用户作出的产品选择或外部权限决定才请求介入。
2. 不再扩展现有手工校准流程，也不把补齐该批次作为项目推进前提。旧记录保留，旧工具供可选人工诊断使用，不是默认入口。
3. 调查与小型原型可以交替推进；正式性能选型和等价结论仍依赖充分证据。缺少完整 WindTerm 基线时，可以验证自己的正确性、各层成本与候选设计；测试护栏或预算提案不等于验收标准。具体性能波动范围必须在可靠基线后与用户明确，主要技术路线也由用户确认。原 M0/M1 名称已由当前 R1–R5 路线接续。
4. 定向逆向优先使用无界面的分析与导出。初期研究范围为接收/线程协作、屏幕/历史存储、绘制调度；2026-10-23 路线整理后，范围由 [PLAN 的逆向安排](../PLAN.md#逆向工作的安排)和当前路标合同接续，包含文字操作、UI、会话及其他需要复刻的行为。每个问题输出事实、推断、未知、下一项独立实验，不以恢复整个私有源码为目标。
5. WindTerm 动态自动化先验证单次闭环，再建设批量运行。使用测试专用 profile 和受控 producer/服务端，每种场景单独验证建连、结果和回收。不得把“可以启动 EXE”当成“可以自动建立会话、验证画面并完成测试”；已验证范围从证据索引查阅。
6. 自动化入口不可用时，记录具体缺口并转向静态分析或自有原型；不回退为反复要求用户操作。遵守工具实际支持范围和操作规则，不通过换一套按键注入规避限制。

## 自动实验约定

- 输入：固定应用哈希、数据哈希、配置、实验编号；不读取日常会话和凭据。
- 执行：有超时、有进程身份、有非交互状态输出；每次唯一目录；失败保留，不默默重试到成功。
- 输出：机器可读原始数据、自动一致性检查、简短报告、明确测量端点。
- 自有原型可暴露解析完成、状态摘要、帧提交等测试接口，但这些端点不等价于 WindTerm 的黑盒端点；帧提交也不等价于显示完成。
- 需要可见桌面的渲染实验另列环境要求；没有画面证据时只完成可验证部分，不降低标准或把 producer_done 改名为 presented_done。
- 在已授权的仓库工作中，代理完成代码、验证、脱敏报告、提交和推送；用户无需审批每个小步骤。目标范围、主要技术路线、验收门槛和重要行为差异依 ADR-0006 单独确认；自动执行授权不等于最终选型授权。外部必要权限仍按实际环境处理，不承诺自动绕过权限。
