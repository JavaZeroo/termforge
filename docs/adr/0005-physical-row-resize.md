# ADR-0005：基础 resize 的物理行契约

> 本文保留 C5 当时的物理行合同与实现记录。窗口章节中的固定度量和尺寸约束已由后续 DPI/zoom 实现扩展；现行窗口行为见 [shell 说明](../../experiments/shell/README.md)，完整现状见 [FEATURES](../FEATURES.md)。

日期：2026-10-23。状态：默认/候选实验行为记录保留；原版一致性与最终产品策略由 #29 / #34 重审，重要差异待用户确认。

按 [ADR-0006](0006-confirmed-project-direction.md)，WindTerm 2.7.0 实际行为优先。本页的裁剪、历史回填、8192 字节重放边界等是现有实现合同；其自身回归通过不构成原版匹配，也不代表用户批准内容丢失等差异。#29 补原版对照并区分匹配、未知和差异；明确原版缺陷的修正或其他重要差异提交用户确认。历史样本和当前回归护栏保留。

## 决策与范围

`Screen::resize(rows, columns)` 接受 1–200 行、1–500 列。该阶段的自研解析器采用物理行裁剪，不推断逻辑段落，不重排软换行或硬换行；这是默认构建的当前行为。缩窄造成的信息丢失是公开的功能限制，不用作吞吐优化依据，也不因此成为最终目标策略。候选的软换行元数据与独立补充合同见下文；原版对照、完整 reflow、备用屏、滚动区交叉语义由 #29 验收。

- 尺寸未变是严格 no-op，保留待换行和组合字符附着。
- 实际尺寸变化时，保留左侧单元格；右侧被截去的内容不会在增宽后恢复。宽字符若在右边界被截断，整个字符及组合标记清空为默认样式空格。可见行和历史行遵循同一列宽规则，完整保留的字符保持文字、组合标记和样式。
- 缩短高度时，先删除底部光标以下可舍弃的行；若光标仍会越界，再将足够的顶部行顺序移入历史，让光标落在最后一行。等价实现先移动 `max(0, cursor_row - new_rows + 1)` 行，再裁剪底部。历史容量和淘汰计数沿用原约定；底部裁掉的行不计为历史淘汰。
- 增高在底部补默认样式空行，不把历史拉回视口。增宽补默认空格。当前 SGR 状态保持，光标列钳制到新边界；清除待换行和组合附着。不将光标自动移离宽字符尾格，沿用既有坐标定位契约。
- resize 不结束字节流，不清空尚未完成的 UTF-8/CSI。后续字节在新尺寸上继续解析。1 列屏幕遇到宽字符沿用严格模式拒绝/Recovery 替换规则。
- 非法尺寸不改变状态。先在副本完成分配和变换，成功后交换；分配失败不留下半变更的核心状态。

## 窗口与运输

窗口使用 12×26 像素单元格、96 逻辑 DPI。正面积 `WM_SIZE` 取整并钳制到核心上限，余数/超限区域画黑；最小化不提交 0 尺寸。实际 DPI/字体切换不在 C5 声明内。

窗口最大跟踪尺寸显式设为核心上限对应的像素尺寸，避免系统默认的虚拟屏幕上限截短自动化请求。保留 DIB 的 dirty 行由快照更新独立累计；不能仅依赖 `BeginPaint` 的更新矩形，否则替换 DIB 或窗口部分不可见时可能留下未重画区域。依据：[MINMAXINFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-minmaxinfo)、[BeginPaint](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-beginpaint)。

UI 独占核心 resize、只读快照与 DIB 替换；尺寸变化使所有新视口行失效。独立 resize worker 持有最多一个正在处理的请求和一个可覆盖的最新请求，不占用输入写线程。UI 持续排空输出，避免同步 resize 与输出背压形成互等。关闭先停止输入、停止并 join resize worker，再关闭 HPCON；UI 此时仍消费尾部字节。

API 依据是 [Microsoft ResizePseudoConsole](https://learn.microsoft.com/en-us/windows/console/resizepseudoconsole)：它更新伪控制台缓冲区尺寸，CUI 程序可通过 console API 查询。测试使用独立 `shell_size_client` 查询 `GetConsoleScreenBufferInfo`，不把请求参数或 API 成功返回当作子进程尺寸证据。

输出流没有 resize 世代边界。UI 会先更新尺寸，已有队列字节和 ConPTY 后续重绘都按当前网格解析；worker 完成只表示最近请求已返回。这里保证静止后尺寸一致和限定脚本场景可继续工作，不保证缩放中每个瞬间无闪烁或历史与 ConPTY 自身重排完全一致。若任一层失败，进入既有关闭流程，不继续冒称同步成功。关闭仍受外部测试监督器时限保护，没有跨版本硬实时保证。

## 验证与重审

`resize_test` 检查明确期望的内容、光标、历史、宽字符/组合/样式、1 列、无效尺寸、部分字节流及 300 次尺寸往返不变量。shell 的 `resize` / `resize-close` 场景在自有非输入桌面操作真实 HWND，分别核对 60×12、100×28，以及洪流后的 72×18，检查 Ctrl-C、退出码和进程/desktop 回收。每次 resize 场景绘制还与独立全量重绘的 RGB 比较；该检查增加开销，结果不用于性能排名。

逻辑行连续性、reflow 与历史坐标的后续交付由 [#29](https://github.com/JavaZeroo/termforge/issues/29)承担。物理行策略不宣称兼容完整终端，也不由该阶段的正确性结果推导 WindTerm 性能差距。

## R2 候选 resize 与历史补充（2026-10-26）

上述物理行合同继续适用于默认自研回退，包括缩窄不可恢复及 resize 改变行版本的规则。显式 `TERMFORGE_BUILD_CANDIDATE_ADAPTER=ON` 的候选采用以下独立合同，不把上游 `Term::resize` 的结果直接称为默认物理行策略或完整 reflow。

- 候选在 resize 时保存有界屏幕快照，识别可跨 feed 的 `CSI ?25l` / `CSI ?25h` 重放。等待期间保留最近一份完整的 resize 后快照，不能把旧尺寸的行和光标放回新尺寸；旧快照仅用于完成时身份匹配。等待超过 8192 字节或 `finish` 时解除冻结并同步实际状态。只有 resize 后的该事务才进入此路径，普通应用隐藏光标不等于已验证的 resize 重放。
- 行键包含换行、wrap、裁剪状态、文字、宽度、样式、组合标记、written 元数据及首个非 padding 单元格的列号。首部未写 padding 的数量决定文字位置，不能因文字字节相同而忽略；只有末尾真正未写 padding 不影响匹配。缓存身份映射也执行相同列位置检查。只有旧、新集合中都唯一且顺序一致的键才能保留 ID/version；重复文本不盲配。最终所有保留行必须具有非零、唯一、严格递增的 ID，冲突行取得新身份和版本，不能让选区或 Find 错配另一段文字。
- 上游增高可先把历史拉入可见区，随后 ConPTY 重放覆盖这些行。候选在完整重放后保留 TermForge 的有界历史，后续同步按 ID 和完整行键合并历史及可见行；同 ID 不同内容不视为同一行。历史容量和淘汰计数仍有界，真实淘汰不恢复，显式清空历史不复活旧行。无完整重放、无法确定语义的 reflow 和任意空白行身份均不在此保证内。
- Find 和选区同时检查 ID、位置、版本和实际投影文本。非软换行的物理列宽或后继 ID 变化不单独使命中失效；从文末新增后继会引入分隔符，仍需重扫。真正的软换行继续要求完整元数据和后继关系。半开选区排除的第 0 列末端空行可以在仍为空白时替换身份；其它行变化、非空端点及实际淘汰仍使选区原子失效。
- 候选合并不表示通用逻辑行 reflow、备用屏/滚动区全语义、所有应用、真实 DPI、呈现完成或性能验收通过。测试辅助读取使用共享文本投影，宽字符 spacer 不算额外空格，显式样式尾空格仍逐字校验。

固定 WindTerm 2.7.0 的限定静态复核中，`0x140238f90` 仅在缩短时进入 `0x140233a30` 的保存路径；增高走 `0x1402ee110` 分配并初始化屏幕行。它只说明该局部分支，不能据此断言整个文本视图增高时不回带历史。本地 `local/analysis/windterm-resize-history-20261026/` 的 44 个定向函数均完成反编译并核对关键汇编，目标 SHA-256 为 `7b10531dccc7cd614ae559f36f1ef518e0c96335637431b4646354823b2804d0`；原始输出留本地。[两次原版运行观察](../research/windterm-resize-text.md)显示固定 Telnet 合成输入的文本完整保留，恢复高度后较早历史重新进入文本坐标视图。屏幕分配与 Document/Scintilla 动态连接、物理格及实际呈现仍未知。
