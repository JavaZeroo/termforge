# ADR-0005：基础 resize 的物理行契约

日期：2026-10-23。状态：C5 / G1 实验采用，产品布局定案前重审。

## 决策与范围

`Screen::resize(rows, columns)` 接受 1–200 行、1–500 列。当前核心没有软换行元数据，故本轮明确采用物理行裁剪，不推断逻辑段落，不重排软换行或硬换行。缩窄造成的信息丢失是公开的功能限制，不用作吞吐优化依据。逻辑行 reflow、备用屏、滚动区的交叉语义须另行实现和验证。

- 尺寸未变是严格 no-op，保留待换行和组合字符附着。
- 实际尺寸变化时，保留左侧单元格；右侧被截去的内容不会在增宽后恢复。宽字符若在右边界被截断，整个字符及组合标记清空为默认样式空格。可见行和历史行遵循同一列宽规则，完整保留的字符保持文字、组合标记和样式。
- 缩短高度时，先删除底部光标以下可舍弃的行；若光标仍会越界，再将足够的顶部行顺序移入历史，让光标落在最后一行。等价实现先移动 `max(0, cursor_row - new_rows + 1)` 行，再裁剪底部。历史容量和淘汰计数沿用原约定；底部裁掉的行不计为历史淘汰。
- 增高在底部补默认样式空行，不把历史拉回视口。增宽补默认空格。当前 SGR 状态保持，光标列钳制到新边界；清除待换行和组合附着。不将光标自动移离宽字符尾格，沿用既有坐标定位契约。
- resize 不结束字节流，不清空尚未完成的 UTF-8/CSI。后续字节在新尺寸上继续解析。1 列屏幕遇到宽字符沿用严格模式拒绝/Recovery 替换规则。
- 非法尺寸不改变状态。先在副本完成分配和变换，成功后交换；分配失败不留下半变更的核心状态。

## 窗口与运输

窗口使用 12×26 像素单元格、96 逻辑 DPI。正面积 `WM_SIZE` 取整并钳制到核心上限，余数/超限区域画黑；最小化不提交 0 尺寸。实际 DPI/字体切换不在 C5 声明内。

UI 独占核心 resize、只读快照与 DIB 替换；尺寸变化使所有新视口行失效。独立 resize worker 持有最多一个正在处理的请求和一个可覆盖的最新请求，不占用输入写线程。UI 持续排空输出，避免同步 resize 与输出背压形成互等。关闭先停止输入、停止并 join resize worker，再关闭 HPCON；UI 此时仍消费尾部字节。

API 依据是 [Microsoft ResizePseudoConsole](https://learn.microsoft.com/en-us/windows/console/resizepseudoconsole)：它更新伪控制台缓冲区尺寸，CUI 程序可通过 console API 查询。测试使用独立 `shell_size_client` 查询 `GetConsoleScreenBufferInfo`，不把请求参数或 API 成功返回当作子进程尺寸证据。

输出流没有 resize 世代边界。UI 会先更新尺寸，已有队列字节和 ConPTY 后续重绘都按当前网格解析；worker 完成只表示最近请求已返回。这里保证静止后尺寸一致和限定脚本场景可继续工作，不保证缩放中每个瞬间无闪烁或历史与 ConPTY 自身重排完全一致。若任一层失败，进入既有关闭流程，不继续冒称同步成功。关闭仍受外部测试监督器时限保护，没有跨版本硬实时保证。

## 验证与重审

`resize_test` 检查明确期望的内容、光标、历史、宽字符/组合/样式、1 列、无效尺寸、部分字节流及 300 次尺寸往返不变量。shell 的 `resize` / `resize-close` 场景在自有非输入桌面操作真实 HWND，分别核对 60×12、100×28，以及洪流后的 72×18，检查 Ctrl-C、退出码和进程/desktop 回收。每次 resize 场景绘制还与独立全量重绘的 RGB 比较；该检查增加开销，结果不用于性能排名。

在 G2 的文字输入、历史浏览或常见 TUI 需要逻辑行连续性时，加入软换行元数据并重新评估 reflow 和历史坐标规则。当前策略不宣称兼容任何完整终端实现，也不由 C5 推出 WindTerm 性能差距。
