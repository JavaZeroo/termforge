## 问题与候选

需要把现有终端状态可靠地画进窗口，并让接收、解析和画面可以独立验证。先在 GDI `DrawText` 与 DirectWrite layout + Direct2D 软件 DC target 两个小候选中比较正确性可观测性、资源复用和接入成本。不据语言标签、主观速度或一次 draw 时长决定产品栈。

## 观察

2026-10-23，固定 3×32 场景、2 个逻辑缩放、2 轮顺序随机运行，共 8 次受控窗口检查通过。真实 HWND 在本程序专用非输入 desktop，正常窗口绘制消息消费只读状态快照；局部更新、旧光标清除、未修改行、前景/背景颜色和 HWND 扩大/还原都有图像检查。`WM_PRINTCLIENT` 与全量 DIB 一致，本机额外 client DC 捕获也一致。它们没有测到用户实际看到图像的时间。

DirectWrite 可从实际绘制 layout 的 glyph run 直接取得字体身份与缺字证据。本机组合重音使用 Consolas，中文 fallback 为 Microsoft YaHei UI；19 个非空格有相应墨迹且未出现 glyph index 0，负例可以被识别。GDI 的局部画面检查通过，但当前没有观测到它实际选中的 fallback 字体；对 GDI 另做的 DWrite 审计只能作参考。

资源预热后，保留每配置 48 个 draw / submission 原始样本和相邻计时器探针。分布仍波动，计时包含 software DC 绘制和 GDI 提交，没有完整观察器校准、用户呈现或持续交互的测量。这些数据不支持候选性能排名。

## 决策

A1 暂采用 **DirectWrite 文字布局 + 可替换的 Direct2D 绘制适配**，沿用小型 Win32 HWND 宿主。当前软件 DC target 作为正确性和集成起点；硬件加速、交换链或其他 UI 框架不在本次决策中。

原因是中文 fallback、组合字符和布局宽度可以与实际被画出的 layout 对应观察，资源也可以复用；这是维护和验证的依据，尚无“更快”的结论。保留 GDI 实验，防止在较弱环境或后端变化时失去小型对照。

状态核心只发布带版本的一致只读快照；呈现层负责资源与光标，更新范围同时包含内容变动和旧/新光标。当前按值复制快照、固定场景缓存与同线程消息驱动足够回答 V1 问题。A1 必须再明确线程间提交、更新合并、背压和取消，不把这个实验结构直接扩张为完整客户端。

## 限制与重审条件

- 完成的是限定场景的 V1 验收。真实物理 DPI 切换、终端 resize/reflow、全字素/复杂整形、emoji、IME、选择/复制与长时运行尚未验证。
- 本机真实窗口 DPI 为 96；144 是显式 1.5× 逻辑缩放。私有 desktop 未激活，`presented_done=null`。
- 使用系统字体的可用性必须显式检查。源码、API 适配和自生成测试图可公开，但本仓库不分发 Microsoft 系统字体。跨平台或可携带字体方案须单独审核许可和来源。
- 软件 DC target、逐格 layout 查找以及全量快照复制可能成为成本来源；当前未将它们认定为实际瓶颈。缓存对固定输入有界，产品路径必须增加预算/淘汰。
- 当 A1 接入持续输出/输入后，若帧预算、延迟、多会话公平性、内存、字体正确性或跨平台维护无法满足需求，重新比较硬件呈现、数据布局与其他候选。任何后端替换应重跑同一状态/光标/字体/图像检查，并记录真实端点和观察扰动。

在 G2 产品后端定案前重审本 ADR。性能是否接近 WindTerm 仍归正式共同负载与端点对照，不能由本 ADR 推出。
