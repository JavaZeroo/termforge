# 工作区尺寸标记残留与原生 viewport

[#63](https://github.com/JavaZeroo/termforge/issues/63) 的工作区 `stage52` 与主区场景 `stage7`，在保留原布局、输入、期限和精确断言的对照中，均指向底部会话的历史重排：原生尺寸标记已经正确，候选屏幕却在标记后保留旧文字。现有 [#51 的 `native_viewport` 修复](native-viewport-resize.md)覆盖这两条已复现路径；本次补充因果核验与原回归，不增加产品改动。

## 固定身份与原失败

旧源码 `188228e`、候选 `.4`、官方 ConPTY `1.25.260930003`、Console flags24 的未插桩 EXE 为 `e81d92a8c7d380d4c33639861180b04935e021bc7c1a5179197c8a9e3c83454a`。原 UI 和主区测试各运行一次，每项三轮均为前两轮通过、第三轮窄布局失败，分别停在 `stage52/client=2048x1120` 和 `stage7`。仅保留单次原窄布局 UI 场景也复现同一失败。

UI 内层20秒、主区内层30秒、每轮外层40秒保持。原三轮方法和两份场景源码与新联合源一致。旧二进制在本批前后哈希一致；旧失败原件保留，不用随后成功覆盖。更早 `3e5b96d` 等缺少对应运输的历史样本不追溯认定同因。

## 单变量对照与直接观察

在 `d6b3f79` 的联合源上临时增加有界 resize/feed、核心/可见快照和尺寸 helper 原生屏幕观察。每对运行使用同一个 EXE，只切换已有 `reflow_history` / `native_viewport` 策略；不清屏、不补发标记、不改变输入或等待条件。UI 与主区分别预设最多两轮，先运行旧策略；若不是原失败就停止，否则执行新策略一次，不重试取绿。

| 场景与会话 | 实际子进程尺寸与原生标记 | 旧策略核心 | 新策略核心及原场景 |
|---|---|---|---|
| UI 底部会话 | `169×11`，整行 `TF_SIZE_169x11` | 同一行带旧 helper 路径残尾，stage52 | 整行精确匹配，完整场景通过 |
| 主区场景的底部会话 | `169×11`，整行 `TF_SIZE_169x11` | 同样残尾，stage7 | 整行精确匹配，完整场景通过 |
| 主区场景的活动主会话 | `112×24`，整行 `TF_SIZE_112x24` | 精确匹配 | 精确匹配 |

失败时底部 resize 请求/完成 generation 分别为 UI `6/6`、主区场景 `4/4`，没有在途任务或输入拒绝。尺寸 helper 实际查询、完整写出标记；同次 transport 含完整标记，核心与可见快照一致。因此捕获红例不符合“子进程尺寸尚未应用”或“查询/输出未送达”；主区的等待失败由底部条件触发。

用保存的 feed 分块和 parser resize 顺序离线回放，旧策略逐字段重现同次失败核心，新策略得到精确标记；活动主会话在两策略下均正确。这将实际运输和调度之外的策略差异独立出来。原因与 #51 一致：通用 reflow 将历史拉回可见区，与原生控制台绝对坐标布局分歧，后续局部写入留下旧行残尾。

UI 与主区各一红一绿的探针 EXE、helper、源码补丁、每轮原件和全部回放保存在本地；公开[白名单记录与哈希](../../experiments/shell/results/2026-10-27-workspace-native-viewport/validation.json)。resize观察上限1024事件/128KiB运输，helper最多读取100000格，各轮未截断。观测读写会扰动调度，离线回放不证明时序或性能等价。原生快照采于 helper 写出后，不等于后续窗口提交或实际呈现。

## 无插桩验收与边界

临时 C++ 按基点字节恢复后，以 `dd533878538490c2464673218ea0000c6467a495` 重建；产品源码与 `c662011` 相同。实际 shell EXE 为 `7f26395942f107297565f50402568650e1e17c5eb23924bee1bfb02c50c60d16`，与诊断 EXE 分列。原 UI 和主区三轮方法重复两批，共12次运行全部通过，包含窄布局、像素/几何负例、会话隔离、真实尺寸、焦点/关闭和 Job/desktop 回收。

同一构建完整 `shell` CTest 在原180秒期限内用时93.62秒完成：40项中37通过、3项按原 hosted clipboard guard 跳过。完整套件内两项工作区方法又各执行原三轮；共18份相关工作区样本均无外层超时，Job active0/terminated0、desktop已回收。其他负例保留原断言，由完整日志单列，不把预期失败记录写成正常运行成功。

回归入口为原 `ShellTests.test_workspace_sessions_resize_and_cleanup`、`test_main_and_bottom_sessions_focus_geometry_and_cleanup` 及 `ctest --test-dir build/candidate -C Release -R '^shell$' -V`。现有 native viewport 核心/原生合成回归继续承担该策略的防退化检查。

本次只闭合 #63 已复现工作区路径及完整 shell 期限；#52 GUI Vim、完整官方配置与 R2 仍未验收。历史缺少原生/运输的记录、默认/system、候选/system、实际呈现和 WindTerm 对照保持独立，不由本次推断。
