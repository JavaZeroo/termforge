# 单次输入的旧来源追踪：限定检查点

实现提交 `5cb61a84ec2a3a8e494c7970fc1c65985002b0f7`，候选 `0.26.1-dev+termforge.9`。本记录固定该实现的原生与 C ABI 检查，不代表 C++ 历史合并已修复、完整 #29/R2 或 WindTerm 等价通过。[验证记录](validation.json)保存源码、二进制和本地日志哈希；后续实现不能覆盖本次仍失败的结果。

## 追踪合同

显式 feed 捕获记录仍存活的旧物理格来源；相同文字的实际重写也失去旧来源。插删和滚动按实际移动传递来源，硬边界独立于文本，待续字素不因捕获被封闭。普通解析不分配来源表。C ABI 通过操作类型与共享 epoch 拒绝错误或过期查询，并在后续成功修改时失效。

`removed_rows` 是过程事件，不是完整擦除/顺序日志。一次输入先淘汰、再 ED3/RIS、再输出时，最终清空代次不能区分清空前后的移除；它也不提供本次新写后又移除的完整内容。调用方不能将该列表当成外部历史保留许可或清空后直接全部补回。

自动软换行另有独立反例：文字、格内容、光标和 WRAPLINE 已正确，但旧硬边界元数据残留。清除残留元数据后该反例通过，未改变真实格内容或光标算法。

## 实际验证

环境为 Windows 11 x64、Rust 1.92.0、Release C++ 适配器。仅检查核心和跨语言接口，没有执行 transport。

| Rust workspace | 163 vendor、10 FFI、2 measure、2 trace、24 feed 集成测试、1 doctest 全通过 | 包括真实 parser 的同字写入、字素续接、插删擦除、宽格清理、硬边界、ALT/RIS、容量与清空、feed→resize 和普通解析一致性 |
