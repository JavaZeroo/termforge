# 历史来源组合、容量区间与待续字素

这是 #29 的实现检查点，尚未解决完整历史视图或原版覆盖政策。代码 `b6764a7` 将 resize/feed 来源接入 C++ 缓存；`eea3a2c` 修复历史删除封闭字素；`95cd2c3` 修复尾部粗体空格来源丢失。候选版本为 `0.26.1-dev+termforge.10`，固定上游、注册表依赖和许可证不变。实现为独立 TermForge 适配与候选补丁，没有导入 WindTerm 私有代码或资源。

## 修复及反例

- 旧缓存与原生片段现在按格来源和独立硬边界合并。固定整段/逐字节重绘保留 `ABCDEFGH\r\nB\r\nC\r\nD`、连续空硬行，以及跨软行 `GHIJ` 的唯一 Find 命中。来源不按相同文字去重；旧文本键仍只服务于限定重放的 UI 身份。
- 无写入的 hide/show 不再重复保留跨历史/可见区的完整旧来源。容量移除按区间作用于已发布、重绘和挂起主屏快照：12 列长行缩至 4 列、容量只淘汰 `ABCD` 后，旧快照曾把它复活；现在复制为 `EFGHIJKL\r\nB\r\nC`，旧坐标/选择失效，`IJKL` 可重新查找和选择，空输入不重复计数。
- 合法空/非空历史前缀删除曾经过 `grid_mut()`，使 `👩` 与后续 ZWJ+`💻` 分开、光标由预期列 2 变为 4。窄职责历史删除接口保留待续字素；完整前缀校验与映射失效规则不变。
- 独立审查发现默认色粗体空格可以是 `written=false`。按 written 裁尾会吞掉其新来源；公开正常/重绘对照真实失败后，改为只裁去完整默认 `Cell`。文字、宽度、样式、标记和字素字段一起参与判断。

## 验证身份与实际失败

[validation.json](validation.json) 保存每次源码、工具命令、日志和二进制身份。Rust `.10` workspace 的 163 vendor、13 FFI、2 measure、2 trace、24 公开 feed 集成及 1 doctest 共 205 项通过。

`eea3a2c` 的 Windows x64 / Release / 显式候选 / 系统 ConPTY 完整 CTest 为 **52/53**。失败的 shell 套件有两项 error：历史 retained frame 与 full redraw 不一致；681 高度选择用例报告 `render API failed`。套件内部共 9 项 skip，其中 8 项实际系统剪贴板门槛未验、1 项为未启用的固定原版失败注入；CTest 级别没有跳过。不得写成完整产品回归通过。

相同旧 shell 二进制、原设置与期限下，两个场景各独立执行一次并保留现场：history 精确复现原错误，退出 2；selection 停在同一 `zoom-before` 前缀，但这次无错误文本、退出 `3221226525 / 0xC000041D`。后者是不同失败，原 API 错误仍未解释。两案未超时，Job active=0、测试 desktop 回收；13 个旧 EXE 与 3 个分发字体文件另保全于本地。未重跑取绿，未操作输入桌面、个人 DPI 或系统剪贴板。

粗体修复在 `95cd2c3` 的公开核心及三个已注册来源用例通过。该源码重新构建后的完整 CTest 仍为 **52/53、9 项内部 skip**：history 退出 2 并报告相同重绘差异；selection 681 这次 stderr 为空、退出 `0xC000041D`，两案均未超时且 Job/desktop 已回收。该结果与旧矩阵分别保存，不证明两个错误具有同一原因。重建后的 `.10` trace 报告回归另有 6/6 通过。

早期 `partial-capacity-frozen.json` 的测试文件哈希在新增旧坐标失效断言后过期，不能用它证明最终测试身份；末次源码和重新构建结果另列。

## 剩余边界

`--source-partial-visible` 仍复制出 `B\r\nABCDEFGH\r\n\r\nC\r\nD`，返回 0 仅表示观察完成，不能计为正确性通过。混合原生行的部分来源拆分、多旧行联合覆盖及完整源顺序仍未闭合。新背景与粗体空格对照不代表所有样式/宽字组合通过。

历史快照仍可能混宽。源码中的“首行宽度用于索引全部行”存在越界访问路径，但尚未证明它就是上述两项运行失败的原因。后续需要临时折行投影及双向源位置映射，同时核对鼠标、高亮、Find reveal 和绘制，不能靠永久裁剪历史或隐藏源文本掩盖。

本次[原版固定状态 CUP+DSR 观察](../../../../docs/research/windterm-resize-text.md#独立观察dsr-后固定状态下的-cup-改写)只确定一次序列改写 H0026；它不是候选缓存政策、未查询状态或普遍覆盖行为的验收。真实不同 DPI、完整系统输入、实验官方后端、实际呈现、性能与最终选型各自保持未完成。
