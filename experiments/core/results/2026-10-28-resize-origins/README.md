# 一次 resize 来源映射与容量计账检查点

源码 `66f1942324060e56974d85ebad3bff04749e7395`，Git tree `7dd044c0cb8d2499a747f5abc70eb1b5d665d08a`；候选 `0.26.1-dev+termforge.8`。这是 #29 的实验基础，**C++ 长历史复制回归仍失败，完整 #29/R2 未完成**。[命令、日志哈希和构建产物](validation.json)分别记录通过与失败，未运行完整产品配置。

## 实际修复与检查

- 同步 resize 在主/备用屏分别导出旧行、目标行、来源区间及移除片段。来源使用旧行 ID 和物理列，不按相同文字去重；硬换行独立保存。宽字单列 footprint、合并和空硬行也保留各自来源边界。
- 高度 4×3、历史容量 1，输入 `ABCDEFGH\r\nIJKLMNOP\r\nQRSTUVWX` 后缩至 1×1。来源检查最初只报告 4 条移除，遗漏原可见区的两行及硬边界；修复后记录 6 条，最终保留 W/X。后续计数修复使原生累计淘汰从 4 增至 10。
- 高度 3×1、历史容量 1，输入 `A\r\nB\r\nC` 后缩至 1×1。实际 A 被容量淘汰，原计数却保持 0；现为 1。普通 `CSI 2S` 同样正确计数；扩高搬移合成空行不增加淘汰，有足够历史容量也不计损失，容量 0 的普通输出滚动仍计真实淘汰。
- C++ 直接调用新 C ABI，检查容量片段、字段布局、非法请求不改输出、epoch 及 feed/finish/discard/resize 失效；备用屏激活时主屏仍独立重排，空硬行保留，备用屏列裁剪不混入主历史。

拆分边界与高度来源均有保存的先失败后通过记录。合并用例首次运行时实现已到位，因此保留初次通过，并以临时移除 grow 映射的负对照验证测试敏感性；不描述为严格的先红后绿。计数测试中曾把未写 cell 的空 `cell_text` 误写为 ASCII 空格，原失败单独保留，修正的是测试表示，不是降低淘汰判据。

## 尚未闭合

映射只描述一次 resize，后续写入前失效；它不是持续写入来源追踪。现有 C++ 历史合并还没有使用此映射，长行重复、空硬行丢失、复制/Find 和视口坐标仍需一起修复。未运行本源码的完整 shell/TUI、系统剪贴板/IME、真实不同 DPI 或实验后端套件；未测新增分配和存储成本，不声明原版等价。
