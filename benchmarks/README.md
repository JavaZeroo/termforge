## 测量矩阵

| 场景 | 主指标 | 正确性/公平性约束 |
|---|---|---|
| 纯文本大输出 | bytes/s、CPU、最终呈现时间 | 不丢行、不以积压队列伪装完成 |
| ANSI 高密度样式 | 吞吐、布局/绘制成本 | 保留样式与控制序列语义 |
| 中文、组合字符、长行 | 响应、内存、布局成本 | 字符宽度、换行、选择正确 |
| 光标覆盖与全屏应用 | 输入延迟、帧响应 | 备用屏幕、滚动区域、resize |
| 百万行历史 | 内存曲线、滚动/搜索延迟 | 固定历史上限，覆盖不同可压缩性 |
| 多会话 | 前台尾延迟、总资源、吞吐 | 公平调度，包含后台高输出 |
| 长时间与关闭重开 | 内存趋势、回收、恢复 | 反复创建销毁，排除缓存暖机影响 |
| SFTP | 大文件/多小文件吞吐、交互延迟 | 内容哈希、固定 RTT/服务端与并发设置 |

## 时间端点

- 生产完成：测试进程已完成输出调用。
- 消费完成：终端处理管线确认输入已消费；黑盒目标未必能直接观测。
- 呈现完成：最终状态出现在画面上；需单独定义视频/视觉或其他可验证观测方法。
- 输入延迟：输入事件到相应画面变化。传入时刻、观察方法和采样频率均需记录。

缺少观测手段时使用 `null` 并写限制，不能用生产完成代替呈现完成。观察工具本身的开销要校准。

## 环境与统计

记录 OS、CPU、RAM、GPU/驱动、显示刷新率/缩放、电源策略、应用版本/哈希、窗口/字体、历史上限、高亮、日志、连接和网络条件。CPU/内存统计需要说明进程树范围；working set 与 private bytes 分开，不当作同一个量。

冷启动与热测试分开；预热次数、重复次数和顺序记录在案，必要时交错运行候选与基准以减少温度/缓存漂移。报告全部有效样本、中位数、分布与失败，不只挑最佳值。不要把不同场景合并为没有解释的总分。

## 文件管理

- `generated/`：生成的大数据，默认忽略。
- `local-results/`：本机原始结果，默认忽略。
- 审查后的公开结果另建 `results/<date>/<case>/`，附重现步骤、原始样本和局限。
- `run-template.json` 是字段草案，后续工具实现前应补 schema/校验规则。空值不是零分或已测结果。
