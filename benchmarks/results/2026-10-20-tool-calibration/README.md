# 工具自检：2026-10-20

这是受控合成 CPU/内存负载的诊断记录，不是 WindTerm 基线，不代表终端吞吐、输入延迟或性能等价。工具尚未通过完整开销校准，#3 保持未完成。

## 检查范围

Python 3.12.10 / Windows 11 build 26200，psutil 7.2.2。自生成 worker 分配 64 MiB，并执行 20000 次 64 KiB SHA-256。一次预热、五对交错 on/off 运行。原始十个 worker 样本和工具源码 SHA-256 见 JSON。后台系统负载、电源/温度未控制到正式基准要求，因此不能将差异全部归因于采样。

| 指标 | 最初：每 100 ms 枚举子进程 | 改为每 1000 ms 发现子进程 |
|---|---:|---:|
| worker 开采样/关采样耗时中位数差异 | +12.15% | -5.65% |
| 每次采样运行的采样器 CPU seconds 中位数 | 1.4375 | 0.09375 |
| 每次运行内 collection_ns 中位数，再跨运行取中位数 | 48.12 ms | 0.24 ms |

资源读取仍为 100 ms。后者降低了枚举开销，但增加漏掉短命子进程的风险。采样器 CPU 时间为首次/最后一次观测之间的增量，不含完整启动与退出成本；collection_ns 不包含写盘，不能当作端到端开销。

负载时间差异绝对值均超过 5% 检查阈值。负向结果不是加速证明；该轮样本不支持“采样开销已合格”的结论。下一步需要控制环境并在 T01/实际终端路径下校准，不能继续挑选重复直到过线。

## 数据与重现

- [initial.json](initial.json)：最初诊断（子进程发现 100 ms）。
- [decoupled.json](decoupled.json)：当前实现诊断（子进程发现 1000 ms）。
- 执行：`python benchmarks/tools/calibrate.py --out benchmarks/local-results/<new-directory>`。
- 初始版本来自本次开发过程中的修正前实现，源码身份记录在 JSON；当前工具不能在不改变参数/源码的情况下复现该旧 revision。对照参数差异明确保留，不将它作为严格产品 A/B。
- JSONL 包含本地进程身份，保留于忽略目录；公开 JSON 仅有 worker 原始样本、采样器汇总、版本与源码哈希，未包含用户名、个人路径或连接数据。由于未公开逐条资源轨迹，公开读者可重算 worker 中位数，但不能独立重算采样器汇总；可用工具重新采集。

## 功能验证

8 项 unittest 通过：全部生成类型的确定性/哈希、独立文本 oracle、覆盖/备用屏幕序列结构、整记录边界/种子/防覆盖、部分写入/零进度、UTF-8 多种分块回放/损坏拒绝、生成器内存有界、Windows 受控子进程发现及 CPU/private bytes 变化。

8 MiB 伪随机 ASCII 负载实际生成 8,388,643 字节（包括完整记录与 marker），SHA-256 为 `ba1c11ddb887a6ec5a64de83fe54ad84eaa861d1e457c98e6491d10c03663181`。这是输入身份，不是终端正确性结果。

功能验证不包括实际终端呈现、完整 VT 兼容性、输入注入、capture、resize 驱动、SSH/SFTP 或长时间稳定性。
